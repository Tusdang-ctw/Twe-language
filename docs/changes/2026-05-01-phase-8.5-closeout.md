# 2026-05-01 — Phase 8.5 closeout: NaN tagging + tracing GC

## Status

Phase 8.5 shipped substantively. All nine sub-sessions (8a through 8i) ran. The two functional deliverables — NaN-tagged value representation and a tracing GC — are implemented, tested, and integrated into both the tree-walker and the bytecode VM. The headline perf criterion ("≥3× speedup vs pre-tag VM" on `cargo bench`) is **not met**; the bytecode VM is currently slower than the pre-tag baseline on tight integer loops. That gap is documented in detail below as a follow-on perf-tuning project.

## What shipped

Across 9 sessions (8a–8i) plus their doc-sync commits (15 commits total in `git log --oneline phase-8.5`):

- **8a — TaggedValue module.** `src/tagged_value.rs` lands. NaN-boxing constants (QNAN, TAG_*), constructors (`from_int`, `from_float`, `from_bool`, `NIL`/`TRUE`/`FALSE` constants), predicates (`is_int`, `is_float`, …), extractors (`as_int`, `as_float`, …), and round-trip property tests. Lifts `unsafe_code` from `forbid` to `deny` with `#![allow(unsafe_code)]` scoped to this one file.
- **8b — HeapBody expansion.** `HeapObject` gains a `body: HeapBody` enum to carry every non-leaf value type — `BoxedInt`, `Percent`, `Quantity`, `Range`, `Tuple`, `List`, `Object`, `Class`, `Instance`, `BcClass`, `BcInstance`, `Function`, `BcFunction`, `Builtin`, `String`. Replaces the 8a stub that only handled strings.
- **8c — VM stack + globals on TaggedValue.** `VM::stack` and `VM::globals` migrate from `Vec<Value>` / `HashMap<String, Value>` to the tagged storage type. Inner pattern matches still operate on a `LegacyValue` shim (deleted at 8f).
- **8d — Tree-walker storage migration.** `Env::bindings`, `Instance::fields`, and frame `saved_returning` / `saved_params` migrate. Same shim pattern.
- **8e — Stdlib field storage migration.** `Object::fields` and `BcInstance::fields` migrate. After 8e every value-typed slot in the runtime is `TaggedValue`.
- **8f — Delete legacy Value (three commits).**
  1. *Structural half:* `Value` becomes a `pub type Value = TaggedValue` alias; every constructor site mass-migrates to the tagged constructors.
  2. *Predicate-dispatch pass:* every `match X.to_legacy() { LegacyValue::Foo(x) => … }` shim site converts to `if X.is_foo() { let x = X.as_foo(); … }`.
  3. *Cleanup:* deletes `LegacyValue` enum, `to_legacy` / `from_legacy` shim, `ToLegacyShim` trait, and three round-trip tests that had nothing left to pin. Exit criterion holds: zero `Value::Foo(_)` enum-variant patterns or constructors anywhere outside `tagged_value.rs`.
- **8g — GC heap allocator.** New `src/heap.rs` with thread-local `Heap`. `HeapObject` grows `mark: Cell<bool>`, `body_kind: HeapBodyKind`, `next: Cell<*mut HeapObject>` headers and is allocated via `gc_alloc` (`Box::into_raw`, replacing `Rc::into_raw`). `Heap::collect(&[&TaggedValue])` runs stop-the-world tri-color mark + sweep with recursive HeapBody scan and cycle detection. `TaggedValue` becomes `Copy` — values are plain 64-bit bit-patterns again, no refcount. Five GC unit tests cover linked-list threading, sweep frees unrooted, mark keeps rooted, mark traverses tuple children, cycle detection terminates.
- **8h — Roots wiring + safepoints.**
  - `gc_collect_with(scan: impl FnOnce())` — closure-based collect entry point. Scan callback walks live roots and calls `mark_value(v)` on each.
  - `gc_should_collect()` — cheap thread-local check (`bytes_allocated >= threshold`) used by safepoints.
  - `gc_set_threshold(n)` — test/bench knob.
  - `Env::scan_roots` — bindings, self_value, returning, active_scene, active_entities. `value::mark_instance` walks an Instance's fields + suspended-fiber saved state.
  - `VM::scan_roots` — stack, globals, builtin_env (delegates), active_scene, active_entities, every active CallFrame's BcFunction constants pool, and top-level on_update. `bytecode::mark_bc_instance` walks a BcInstance's fields + fiber_stack.
  - `mark_bc_function_constants` — walks a `BcFunction`'s chunk constants. Used both by `mark_body` (when reaching a BcFunction through a TaggedValue) and by `VM::scan_roots` (where active CallFrame functions are held as naked `Rc<BcFunction>` with no TaggedValue path).
  - `mark_body` updates: `BcFunction` walks chunk constants; `BcClass` walks methods + states' inner BcFunctions (`on_entry`, `every_clocks`, `on_update`, `on_render`, `on_key_press`, `on_predicates`); `BcInstance` additionally walks `fiber_frames`' resumption-function constants.
  - Eval safepoint: `run_block` checks between statements.
  - VM safepoint: dispatch loop top checks between bytecode instructions; `ip` is sync'd to `self.frames` first so root scanning sees a consistent state.
  - Stress tests under `gc_set_threshold(0)`: `snake_runs_under_aggressive_gc` (10 ticks of `examples/snake.twe`'s state-machine + entity logic) and `vm_entity_tick_runs_under_aggressive_gc` (50 spawned entities through the bytecode VM). Both exercise the full roots-scanning path with collect firing on every safepoint.
- **8i — Bench + inline-tuning pass.** Adds `#[inline]` to the hot TaggedValue predicates and constructors. Adds `#[inline]` to `gc_should_collect`. Caches `slot_base` in the VM dispatch loop alongside `current_func` / `ip`. Bench harness already existed (`tests/bench.rs`); ran against three baselines documented below. The 3× exit criterion is not met — see below.

## What slipped

### The 3× speedup criterion

Phase 8.5's hard exit criterion (per `docs/05-roadmap.md` §"Phase 8.5"):

> `cargo bench` reports ≥3× speedup on the existing benchmarks vs. pre-tag VM.

This is not met. Comparing post-8i bytecode VM (`HEAD`) to pre-tag bytecode VM (`962fa77`, the commit just before session 8a started), measured via `cargo test --release --test bench -- --ignored --nocapture`:

| Workload | pre-tag bc (µs) | post-8i bc (µs) | post-8i / pre-tag |
|----------|-----------------|-----------------|-------------------|
| fib(25) | 54,931 | 66,533 | 1.21× slower |
| sum_loop(100k) | 64,205 | 108,103 | 1.68× slower |
| method_call(10k) | 6,995 | 12,318 | 1.76× slower |
| list_iter(10k) | 9,283 | 12,182 | 1.31× slower |
| scene_tick(1k) | 707 | 808 | 1.14× slower |
| entity_tick(500) | 1,030 | 1,263 | 1.23× slower |
| entity_tick(500) × 60 | 12,485 | 16,432 | 1.32× slower |

Direction goal was 3× **faster**. We're 1.1×–1.8× **slower** on every benchmark. So the gap to the criterion is 3.3×–5.4× depending on workload.

Caveats on these numbers:

- The current bench harness times each workload once per invocation. Per-run variance is large (40% swings on the same workload across consecutive runs). A criterion-style multi-iteration harness would be needed to make precise per-optimization claims; that's out of 8i scope.
- The numbers here are medians by inspection across a handful of runs, not formally bounded.
- Tree-walker speeds also bounce dramatically across runs (sum_loop tree: 30–95k µs across consecutive runs on identical hardware). The bytecode-VM-vs-tree-walker ratio (`bc/tree`) is therefore an unreliable single-run metric.

What we can claim with confidence: **the bytecode VM is comparable to the tree-walker on most workloads**, and **slower than the pre-tag bytecode VM** on tight integer / list / method-call loops.

### Where the regression likely came from

Bisecting at `82ca80a` (post-8f, predicate-dispatch shipped, no GC yet) showed 8f had already regressed sum_loop from 64ms → 98ms versus pre-tag. So the regression was introduced during the 8c–8f migration to predicate dispatch, not by 8g (GC) or 8h (safepoints). Strong suspect: the `if l.is_int_or_boxed_int() && r.is_int_or_boxed_int() { … } else if l.is_float() && r.is_float() { … }` chain in `binary_arith` / `compare` doesn't compile to as tight a jump table as the pre-tag enum-match did. 8h's safepoint check did add ~30% overhead on sum_loop on top of that, but inlining `gc_should_collect` (in 8i) clawed most of that back.

### Follow-on work to close the gap

Captured here as the agenda for a dedicated post-Phase-8.5 perf phase (possibly Phase 8.6 or absorbed into v0.3 perf work):

1. **Switch to a criterion-based bench harness** for stable measurement. Without it, every "did this help?" question is dominated by noise.
2. **Profile the dispatch loop** with `samply` or VS profiler to identify actual hot instructions. Educated guesses got us this far; profiling beats guessing past this point.
3. **Reorder predicate-dispatch fall-through.** Put `int + int` first in `binary_arith` / `compare` since it's by far the hottest case.
4. **Consider inline caches** for monomorphic call sites (similar to V8 / Luau).
5. **Investigate the regression at 8f specifically.** A controlled diff between pre-tag's enum-match and post-8f's predicate-dispatch on a single hot path (e.g. `binary_arith`) might reveal a small fix that closes most of the gap.
6. **Consider switching opcode dispatch from `match` to a direct-threaded interpreter** (computed goto). Doable on stable Rust via tail calls + `become` (when stabilized) or via inline assembly. *Crafting Interpreters* §24.7 is the design template.

None of these is in 8i scope — each is a session of its own.
