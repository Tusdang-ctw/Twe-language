# web3d-M5 plan: sessions

**Opened:** 2026-10-01
**Milestone:** web3d-M5, the measured LLM benchmark ([pivot note](2026-09-27-web3d-pivot.md), M5 row and kill line)

**Exit criterion:** published numbers, with confidence intervals and ablations, comparing Twe against a Python + pygame-ce baseline on the same tasks graded the same way.

**Kill line:** if Twe with the verify loop does not beat the Python baseline on pass@1, Twe stops marketing LLM authoring as its moat, and a root-cause note says why.

**Order:** M5 runs before M6, by the maintainer's choice (2026-10-01).

## What already exists, and what's wrong with it

Phase 33 shipped the pieces as separate tools:
- `src/llm_loop.rs`: a provider trait with fixture and shell-command providers; generate → `twec verify` → retry.
- `src/llm_eval.rs` (`twec eval`): grades a program by its stdout after N frames. There are three toy suites in `eval/`.
- Studio's `llm.rs`: a second, async provider layer (Anthropic, Ollama) and a SEARCH/REPLACE edit protocol, drifted from `llm_loop`.

None of it measures anything:
- **Grading by stdout** rewards programs that print the right words, not programs that behave.
- **No input.** Nothing can test a game that responds to keys.
- **No samples, statistics, cost or baseline.**

## Method

**Behaviour, not text.** A task is graded by running the program headless for N fixed ticks while an input trace (the M4 replay format) is fed in. Probe expressions are then evaluated on the final world, e.g. `entities.count(Coin) == 0` or `player.pos.x > 10`.

**Every task is validated before any model sees it:**
- a reference solution passes;
- the starter fails;
- each probe fails on at least one deliberately broken variant, so no probe passes vacuously.

**The same harness grades both languages.** The Python baseline gets the same task text, input trace and probes, run through a small pygame-ce driver under SDL's dummy video driver.

**Statistics:**
- n = 5 samples per task;
- pass@1, and pass@k by the unbiased estimator (Chen et al. 2021);
- 95% confidence intervals by bootstrap over tasks;
- rounds-to-pass, verify/syntax error rates, tokens, cost and wall time.

**Pinned models.** Current Claude models reject `temperature` (sampling is fixed), so a run is pinned by model id plus effort level. Every response is cached by a prompt hash, so a run can be re-graded without new API calls.

## Sessions

1. **`crates/twe-llm`.** The shared provider and edit-protocol crate:
   - Providers: Anthropic Messages API, OpenAI-compatible (Ollama / llama.cpp), shell command, fixture. HTTP is blocking, through `ureq` behind an off-by-default `http` feature.
   - One reply type carrying text, stop reason, token usage (including cache reads and writes) and cost.
   - One edit protocol: SEARCH/REPLACE blocks or a whole fenced file, parsed in one place.
   - `src/llm_loop.rs` moves onto it.

   Done 2026-10-01 ([note](2026-10-01-web3d-m5-twe-llm.md)):
   - 17 crate tests, including a local-server test of the real HTTP path (with a retried 529);
   - `llm-loop` rounds are now one conversation, with replies as edits against the current file;
   - not called live yet: no credentials on this machine.
2. **Behavioural grading.**
   - The task format `bench/tasks/<id>/{task.md, starter.twe, solution.twe, input.trace, checks.toml}`.
   - A headless runner that feeds the trace one command per tick, then evaluates the probes.
   - `twec bench check <task>` validates a task: reference passes, starter fails, every probe is mutation-checked.
3. **Bench v0: 20 tasks** across three tiers (logic; entities and state; input-driven play), each with a reference solution, validated by session 2's checker.
4. **`twec bench run`.**
   - Samples per task, with the verify loop (at most 4 rounds) on or off.
   - Metrics, JSONL transcripts in `bench/runs/<date>-<model>/`, the response cache, `twec bench regrade`.
   - A scorecard with bootstrap confidence intervals.
5. **The Python baseline.**
   - A pygame-ce driver (dummy video driver) that runs a program's `Game` class against the same input trace.
   - Probes evaluated on the game object.
   - The 20 tasks ported with Python reference solutions, validated the same way.
   - The plan's "Python + pygame" baseline needs `pip install pygame-ce` on the bench machine.
6. **Bench v1: 60 public tasks**, plus tooling for a hidden set kept outside the repo. Contamination controls:
   - a canary GUID in every task;
   - the primer frozen per bench version;
   - flagging completions that match the corpus verbatim;
   - a rotation rule for later versions.
7. **Ablations and Studio.**
   - Primer on/off, verify feedback on/off.
   - GBNF-constrained decoding for local llama.cpp models, if one is available on the bench machine.
   - Studio's `llm.rs` moves onto `twe-llm`, ending the drift.
8. **Corpus:** `twec mutate` triples grown to ≥ 500.
9. **Runs, results, closeout.**
   - Pinned models through the full matrix.
   - `bench/results.md` with intervals and ablations.
   - The kill-line verdict.

   **This session spends money and needs the maintainer's API key.** Before it runs, the maintainer approves a cost estimate built from session 4's measured per-sample cost.

## Rules for this milestone

- **Commits:** `web3d-m5:`. Closeout note at the end.
- **No language changes.** The benchmark measures Twe as it is. A failure pattern that suggests a language change is written down for later, not fixed mid-measurement: changing the language mid-benchmark would make results incomparable.
- **Honest scoring.** The harness is validated before any model is scored on it. Every reported number has its sample count and interval. Results where Twe loses are published like the rest.
- **No live API calls in tests.** Tests use the fixture provider and recorded replies.
