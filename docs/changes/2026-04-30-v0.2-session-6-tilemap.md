# 2026-04-30 — v0.2 session 6: tilemap (stdlib-builtin form)

## Status: shipped. Closes the Phase 8 "tilemap rendering + collision" line item with the stdlib-builtin form. The language-level `tilemap Name:` block syntax from Example 9 gets a parser pass in a follow-on session — same runtime, nicer surface.

## Background

`docs/01-examples.md` Example 9 is the tilemap pressure test, scheduled for v0.2 per the post-Phase-7 roadmap. The full feature has three layers:

1. **Runtime + collision** — what this session ships. Tilemap data, per-tile rect rendering, world-coords-to-tile lookups, `solid` trait queries.
2. **Block syntax** — `tilemap Dungeon:` parser hooks. Defers to keep this session shippable; lexer / AST / parser changes are non-trivial.
3. **Sprite-based rendering** — replace the per-trait colored rect with sprite-atlas frames. Rides Phase 9 (visuals + atlases).

This session closes layer 1. Twe scripts can build, render, and collision-query a tilemap *today* via stdlib calls; the block-syntax sugar is purely cosmetic.

## What ships

### `tilemap(layout, tile_size, tiles)` — build a tilemap value

```twe
let map = tilemap(
    layout: "##.\n.~.\n...",
    tile_size: 16,
    tiles: [
        (".", "floor", ["walkable"]),
        ("#", "wall", ["solid"]),
        ("~", "water", ["walkable", "slow"]),
    ]
)
```

Returns an `Object { kind: "tilemap" }` with fields:

- `layout` — the original string (for inspection / hot-reload diffs).
- `tile_size` — pixels per tile (square).
- `width`, `height` — grid dimensions in tiles.
- `cells` — `List<List<String>>`, per-row, per-column tile name. Empty string for chars not in the spec.
- `tiles` — `Object { kind: "tile_specs" }` keyed by tile name; each value is `{ name, traits: List<String> }`. Twe code can introspect.

The `tiles` argument is a list of `(char, name, traits)` 3-tuples. `traits` accepts a `List<String>` or `nil` (no traits). Errors are precise: tuple-shape mismatch, char-string with multiple chars, non-string trait — each names the offending entry's index.

The layout string uses `\n` to separate rows; per-line whitespace is trimmed and blank lines are dropped, so triple-quoted multiline layouts can use indentation freely.

### `tilemap_render(map, at)` — draw

Iterates every cell, draws a colored `rect(...)` per tile via `push_rect` (a thin wrapper over the existing `draw_rect` builtin to skip the kwargs-binding path on the inner loop). Color is keyed by trait:

- `solid` → light gray.
- `trigger` → yellow.
- `slow` → blue.
- `walkable` → dark gray.
- *no trait found* → magenta (visible "missing tile" indicator).

This keeps v0.2 dependency-free. Phase 9 will let each tile carry an explicit color or a sprite-atlas frame instead of being keyed off traits.

### `tilemap_at(map, x, y)` — query tile name

Pixel-coords → tile-coords (floor division by `tile_size`) → tile name. Out-of-bounds reads return `""`. Useful for "what surface am I standing on?" — see `examples/tilemap_demo.twe` where it gates the slow-on-water effect.

### `tilemap_solid_at(map, x, y)` — collision query

Convenience wrapper that returns `true` when the tile at `(x, y)` carries the `solid` trait. The most common collision query; out-of-bounds reads return `false` (the world ends, but it's not solid). Used for the "slide along walls" pattern in the demo.

### `src/stdlib.rs::install_tilemap`

New install function called from the top-level `install`. All tilemap helpers live here — no separate `src/tilemap.rs` module since the feature is purely stdlib-shaped. When the `tilemap Name:` block syntax lands, it'll likely call into the same `tilemap_build` body via a thin wrapper.

### Tests

4 new tests in `tests/eval.rs`:

- `tilemap_builds_grid_from_layout_and_specs` — width / height / tile_size end up on the returned object.
- `tilemap_at_reports_tile_name_per_pixel` — coordinate → name lookup; out-of-bounds returns `""`.
- `tilemap_solid_at_reflects_solid_trait` — solid trait gates collision.
- `tilemap_rejects_malformed_tiles_arg` — non-3-tuple in the `tiles` list errors clearly.

### Example

[examples/tilemap_demo.twe](../../examples/tilemap_demo.twe) — a 16-wide × 7-tall dungeon room with walls + a water patch, and a hero blob that you move with WASD. Walls block movement; water halves speed. Demonstrates the slide-along-walls pattern (axis-by-axis collision tests).

## Not in scope

- **`tilemap Name:` block syntax** (Example 9 grammar). Lexer + AST + parser hooks. Follow-on session — same runtime layer.
- **Spawn points** (`Dungeon.spawn_point` from Example 9). Needs designation tiles + a stdlib helper. Follow-on.
- **`enter Dungeon` keyword** for "switch to this tilemap" semantics. Follow-on.
- **`on hero.enter(tile: exit)` event handlers** — typed event glue between entities and tile types. Phase 9-10 territory; needs the typed-event-handler design conversation.
- **Sprite-based tile rendering** — Phase 9 with atlases.
- **Dynamic tile mutation** (`map[3, 5] = "floor"`). Tiles are immutable post-build today. Add when a real game wants destructible terrain.
