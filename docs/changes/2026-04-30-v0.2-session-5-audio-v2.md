# 2026-04-30 — v0.2 session 5: audio v2

## Status: shipped. Closes the Phase 8 "audio v2" line item with the realistic surface macroquad's quad-snd backend supports — volume control + looping + stop + per-handle volume adjust. Pitch and mixer-channel routing remain deferred (not supported by the underlying engine; would need a different audio backend).

## Background

v0.1 shipped a minimal `sound.load(path)` + `sound.play(handle)` pair via `play_sound_once`. That's enough for "fire and forget" SFX but bottoms out for any real game: no volume, no music looping, no way to stop a held sound, no way to fade out. v0.2's audio-v2 line item closes those gaps with what the existing macroquad/quad-snd stack actually offers.

## What ships

### `sound.*` extensions

```twe
sound.play(handle)                    # v0.1 — one-shot at default volume
sound.play_at(handle, volume)         # NEW — one-shot with explicit volume
sound.stop(handle)                    # NEW — stop all instances of this handle
sound.set_volume(handle, volume)      # NEW — adjust volume of in-flight instances
```

Volume is clamped to `[0.0, 1.0]` at the boundary; values outside that range silently clamp rather than error (matches macroquad's behavior and avoids cliff-edge runtime errors when game code computes volume from gameplay state).

### `music.*` namespace (new)

```twe
music.play(handle)                    # looped play at default volume
music.play_at(handle, volume)         # looped with explicit volume
music.stop(handle)                    # stop the looped instance
```

Same underlying handles as `sound.*`; the difference is `looped: true` is wired in the `PlaySoundParams` for these calls. Encourages a clean mental separation between SFX and BGM in user code.

### Calling-convention note

Twe's calling convention requires every kwarg to be supplied — there's no default-value support yet (it's an open design question per `CLAUDE.md` §"What is open"). So configurable plays get their own fixed-arity builtins (`play_at`) rather than overloading `play` with optional kwargs. When default-values land, the per-arity proliferation can collapse into a single `sound.play(handle, volume:, looped:)` form.

### Implementation

Refactored `sound_play` into a shared `play_sound_path(path, callee, volume, looped)` helper that:

1. Looks up the decoded `Sound` in `SOUND_CACHE`, decoding on first use.
2. Calls `macroquad::audio::play_sound(snd, PlaySoundParams { volume, looped })`.

Every audio builtin pulls its handle's path via the new `sound_handle_path(value, callee_name)` helper — single place that validates `Object.kind == "sound"` and pulls the `path` field. Errors carry the calling builtin's name for clarity.

`SOUND_CACHE` is the same `RefCell<HashMap<String, Sound>>` that v0.1's `sound.play` uses — `clear_asset_caches` (called on hot reload) drops everything. New cache is populated lazily on first `sound.play_at` / `music.play` of any path; the v0.1 path already pre-warmed the cache for handles played via `sound.play`, so cross-builtin handle reuse is free.

### What's not in scope

- **Pitch** — quad-snd doesn't expose it. macroquad's PlaySoundParams has only `volume` + `looped`. Adding pitch needs a different audio backend (rodio / kira / cpal-driven custom mixer). v1.0 follow-on or v1.x.
- **Per-channel mixer routing** — quad-snd is a flat mixer. Same backend constraint. The `music.*` namespace gives a *semantic* split (SFX vs BGM) but they share the master output.
- **Streaming audio** — `load_sound_from_bytes` decodes the entire file. Long music tracks load fully into memory. Streaming would also need a backend swap.
- **Crossfade / fade-in / fade-out** — mentioned in the v0.2-v1.0 plan; deferred until pitch/mixer work motivates a backend swap.

The semantic surface (`sound.*` and `music.*` namespaces) is forward-compatible: when a richer backend lands, the same Twe-side calls keep working.

### Tests

2 new tests in `tests/eval.rs`:

- `stdlib_installs_audio_v2_surface` — pin every new builtin name on both `sound` and `music`.
- `audio_builtins_reject_non_sound_handles` — `sound.stop("string")` errors with a useful message.

Tests don't exercise actual audio output (would require platform audio + an asset). Manual exercise via [examples/audio_demo.twe](../../examples/audio_demo.twe).

### Example

[examples/audio_demo.twe](../../examples/audio_demo.twe) — press R for SFX, M to toggle music, S to stop, mouse wheel for volume. Renders a volume-bar HUD using the rect drawing primitive. Loads `examples/assets/silence.wav` (intentionally silent — drop your own WAV / Ogg in to hear it).
