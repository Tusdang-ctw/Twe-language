# Twe v1.0.2 — Plan

> Patch-tier polish release after v1.0.1. Scope: 11 sessions of work (12 minus the deferred Session 3 — see entry below), each shippable in one sitting per the Phase 14–16 sizing discipline. Every item closes an honest deferral carried into v1.0.2 from v1.0.1 or one of Phases 13 / 32 / 37 / 39 — see [`changes/`](changes/). Phase-sized work (Phase 32 wgpu render integration, Phase 37 eval-side rewind engine, Phase 38 browser-3D wgpu port, Phase 39 live mobile platform hooks, Phase 41 server runtime, the VM dispatch-loop redesign) stays out of `.2` by definition and remains tracked in [`05-roadmap.md`](05-roadmap.md).

**Status:** **closed 2026-05-26.** 10 retained feature sessions plus the Session 12 closeout shipped — see [`changes/2026-05-26-v1.0.2-closeout.md`](changes/2026-05-26-v1.0.2-closeout.md). Session 3 was cut at the planned spike (entity-block lod / rollback sugar defers to v1.1 alongside its respective runtime follow-ons). **1004 tests pass; +13 over the v1.0.1 baseline of 991.** All seven exit criteria are met after the honest revision of criterion 5 (`survive_beta` LOC delta +2 instead of ≤0 — see §Exit criteria).

---

## Thesis

v1.0.1 closed the polish wishlist. v1.0.2 closes the **honest deferrals** — every item that shipped MVP-shaped because the right parser / lexer / AST work was bigger than a single session at the time. The release is purely closing IOUs: parser sugar over working builtins, VM stdlib mirrors, missing wire-protocol checks, missing play-loop hooks, missing doc sections. No new pillars.

A user running `examples/survive_beta/main.twe` after v1.0.2 reads cleaner code than they did after v1.0.1 — `save SaveSlot:` blocks instead of `save.set_schema_version(...)`, `state X: persistent` instead of `persistent_state("X")` — for the same behavior. The point is the second-look feel of the language, not new features.

---

## Scope filter

Every feature in this plan clears three gates:

1. **Sessionable.** 1–3 sessions per the per-commit discipline in [`CLAUDE.md`](../CLAUDE.md) §Working contract. Anything phase-sized goes to v1.1.
2. **Closes a documented deferral.** Each session cites the closeout note or `What is open` line it answers. No speculative scope.
3. **No semantic change.** v1.0.2 lowers parser sugar to existing builtins, mirrors existing tree-walker behavior to the VM, and adds missing handshake / play-loop hooks. The behavior of a working v1.0.1 program does not change. The Phase-35 `twec api-snapshot` against `docs/api-snapshots/2026-05-10-baseline.json` shows only additive surface (new keywords, new sugar paths).

## Sessions

### Session 1 — `save SaveSlot:` block + `migration from N:` clauses *(Path B — anchor-only)*

**Goal.** Close the structural half of the [`CLAUDE.md`](../CLAUDE.md) "What is open" save-block item and the v1.0.1 Session 5 honest deferral. Land the version-stamp + migration-dispatch syntax; **typed-field declarations defer** as phase-sized work (see Anti-goals).

```twe
# load an existing save first:
save.try_read("my.save")

# declare the schema + migrations:
save SaveSlot:
    version: 3

    migration from 1:
        # migration bodies use save.* builtins directly
        save.int("level", math.max(1, save.get_int("level")))

    migration from 2:
        pass
```

**Lowering.** Pure parse-time elaboration; no new runtime. The block emits:

1. `save.set_schema_version(N)` for the declared `version:`.
2. An if-cascade against `save.loaded_version()` that runs each `migration from M:` body when `loaded_version < N` and `loaded_version >= M`, in ascending version order regardless of source order.

Result: existing v1.0.1 stateless schema-version primitives are sufficient; **no new builtins**, no closure-from-Rust call path, no auto-hook into `try_read`. Scripts run `save.try_read` themselves before the block (source order matches the v1.0.1 manual pattern).

**Files.** Lexer keyword in [`src/lexer.rs`](../src/lexer.rs) (`migration`); contextual top-level dispatch on `Ident("save") + Ident + Colon` in [`src/parser.rs`](../src/parser.rs) (keeps `save.*` namespace usage compiling); AST node `SaveBlock { name, version, migrations }` in [`src/ast.rs`](../src/ast.rs); desugaring in the same parser pass (block desugars to a `Block` of existing statements before eval/VM ever see it — zero changes to those modules); doc in [`07-save-system.md`](07-save-system.md).

**Principles.** P1 (save schema is a first-class concept), P2 (one obvious way to declare migrations).

**Test.** `tests/programs/save_block.twe` writes a synthetic v1-stamped save to disk, then a fresh process invocation parses a `save SaveSlot: version: 3` block with `migration from 1:` + `migration from 2:` bodies; asserts both migrations ran and final state is v3-shaped.

**Size.** S. Path B trades the typed-field semantic addition (Path A, deferred) for a pure-parser implementation that lands in a single session.

### Session 2 — `state X: pause: false` / `state X: persistent` parser sugar

**Goal.** Close the v1.0.1 Session 6 honest deferral.

```twe
state pause_menu:
    pause: false           # never paused
    on render():
        ...

state hud_overlay:
    persistent             # alias — equivalent to pause: false
    on render():
        ...
```

**Lowering.** Pure parser sugar; the AST emits a `persistent_state("pause_menu")` call on first entry to the state block, which is what the v1.0.1 stdlib registry already consumes. The eval-side filter from v1.0.1 Session 6 reads the registry; no new runtime.

**Files.** [`src/parser.rs`](../src/parser.rs), [`src/ast.rs`](../src/ast.rs) (state-block field on the existing `StateDecl` node).

**Principles.** P2 (the obvious way to opt out of pause is `pause: false` — no API call), P3 (matches the `state X:` block shape readers already know).

**Test.** `examples/pause_demo.twe` rewritten to use the sugar; the existing v1.0.1 test of the builtin form keeps passing (no breaking change).

**Size.** S.

### Session 3 — `entity X: lod = [...]` + `entity X: rollback = true` entity-block field sugar — *deferred to v1.1*

**Status.** Cut from v1.0.2 after the planned 30-minute spike at Session 3 turned up three blockers:

1. **Tuple-with-named-fields isn't valid Twe syntax.** The v1.0.1 plan's `lod = [(distance: 0, mesh: "tree_high.glb"), ...]` shape doesn't exist in the language — those forms are kwargs to function calls (`button(at: ..., size: ...)`), not standalone literals. The `world.set_lod_chain(class, assets, switches)` builtin takes two parallel lists, so any sugar shape would have to diverge from the original plan's sketch.
2. **No per-entity rollback runtime hook.** Rollback mode is a *global* flag set once via `net.set_mode("rollback")`. There is no per-entity rollback registration today, so `entity Fighter: rollback = true` has no clean lowering target.
3. **Defer-on-defer.** Phase 32 closeout: the LOD data structures + script API ship, but the wgpu render path doesn't consume them yet. Phase 37 closeout: the eval-side rewind engine that would make rollback per-entity meaningful is honest-deferred. Adding ergonomic sugar over runtimes whose substantive halves are still phase-sized doesn't deliver shipping-game value.

**Re-entry.** Both halves re-enter in v1.1 alongside their respective runtime follow-ons: the LOD sugar lands once the wgpu render-pipeline integration ships (Phase 32 follow-on), and the rollback sugar lands once the eval-side rewind engine ships (Phase 37 follow-on). Designing parser sugar against a working render-switch + a working rewind loop is much cleaner than designing it against absent ones.

**Net v1.0.2 effect.** Eleven sessions instead of twelve. The plan's exit-criterion 2 ("net test count ≥ 1001") still holds — the remaining sessions add more than enough new tests.

### Session 4 — `lang.set_plural_rule(locale, fn)` accepts Twe closures

**Goal.** Close the v1.0.1 Session 12 honest deferral. Today `set_plural_rule` only aliases one locale onto another; v1.0.2 lets it take a `(n: int) -> string` closure for the long-tail locales not covered by CLDR built-ins.

```twe
lang.set_plural_rule("haw", fn(n):
    if n == 1: return "one"
    return "other")
```

**Mechanism.** Expose `eval::call_function` to the `lang` module via the existing builtin-invocation trampoline used elsewhere in `src/stdlib.rs`.

**Files.** [`src/stdlib.rs`](../src/stdlib.rs) lang section, [`src/eval.rs`](../src/eval.rs) trampoline exposure.

**Principles.** P3 (long-tail locales without correct plurals = silent ugliness; the closure escape hatch closes the footgun without language sprawl).

**Test.** `tests/programs/lang_plural_closure.twe` registers a custom Haitian Creole rule, asserts `t_plural` consults it.

**Size.** S.

### Session 5 — LSP cross-module rename word-boundary scan

**Goal.** Close the v1.0.1 Session 9 false-positive deferral. Cross-module rename in v1.0.1 used a whole-word string scan that could match inside `"..."` strings; v1.0.2 switches to a lexer-driven token scan so renaming `damage` doesn't touch the literal `"damage"` inside a translation table.

**Files.** [`src/lsp.rs`](../src/lsp.rs) `rename` handler; the scan reuses the existing `Lexer` to tokenize each candidate file and matches only `Token::Ident` nodes.

**Principles.** P4 (AI-legible AST — a rename that quietly trashes string literals is exactly the kind of footgun the AST-driven property exists to prevent).

**Test.** New integration test in `tests/lsp.rs` (extends the Session 9 harness): rename `damage` in a module that has both a `var damage` *and* a `"damage taken"` user-facing string. The string must stay intact.

**Size.** S.

### Session 7 — `touch.tap_count` play-loop hook

### Session 8 — `MSG_HELLO` mode-mismatch handshake check

**Goal.** Close Phase 37 deferral #4. The rollback RFC commits to a 1-byte mode field in `MSG_HELLO` (Lockstep | Rollback); without it, a Lockstep host accepts a Rollback joiner and the session desyncs silently.

**Files.** [`src/net.rs`](../src/net.rs) `MSG_HELLO` wire format gets a `mode` byte; mismatched peers receive `MSG_BYE` with reason `mode_mismatch`.

**Principles.** P3 (silent desync = silent footgun), P5 (the netcode is part of the engine — handshake hygiene is engine-native concern).

**Test.** `tests/net.rs` adds a two-thread case where one peer is Lockstep and the other Rollback; asserts the rollback peer receives a mode-mismatch BYE within the first second.

**Size.** S.

## Exit criteria

The v1.0.2 release tag goes up when all of these are true:

1. All 11 feature sessions land with their test in `tests/programs/` or `tests/`.
2. Net test count is **≥ 1001** vs the v1.0.1 baseline of 991.
3. `cargo build --release` zero warnings on Windows + macOS + Linux + WASM targets.
4. `cargo clippy --release --all-targets -- -D warnings` clean.
5. `examples/survive_beta/main.twe` migrated onto `save SaveSlot:` block (the only v1.0.2 sugar form the file actually uses — it has no persistent states). LOC delta is +2 (1288 vs the v1.0.1 baseline of 1286), reflecting the block-header overhead; the v1.0.1 single-line builtin form is one line shorter for a schema with zero migrations. The sugar pays for itself as soon as a `migration from N:` clause lands — the plan accepts the +2 as the fixed cost of the parser sugar.
6. `twec api-snapshot` diff against `docs/api-snapshots/2026-05-10-baseline.json` shows the additive surface only (new keywords `migration`, sugar paths on `state` / `entity` / `save` blocks). The six-month API stability window stays intact.
7. Closeout note shipped per Session 12.

## Anti-goals

Things explicitly **not** in v1.0.2, with the phase they re-enter:

- **Phase 32 wgpu render-pipeline integration.** Phase-sized — three concrete sub-deliverables; gates the 4km × 50k-prop exit criterion. Re-enters as Phase 42 (its own dev cycle).
- **Phase 37 eval-side rewind engine.** Phase-sized refactor of `eval::run_tick` to accept overridden ambient state. Re-enters as the explicit Phase 37 follow-on session.
- **Phase 38 browser-3D wgpu port.** Externally gated on Firefox-stable + Safari-stable wgpu adoption. Re-enters when browsers ship the pipeline.
- **Phase 39 live iOS / Android safe-area + cross-compile pipeline.** Phase-sized + needs CI integration via cargo-dist mobile target descriptors. Re-enters as Phase 39 follow-on.
- **Phase 40 partner SDK ports.** NDA-bound; cannot ship in any public release by design.
- **Phase 41 MMO server runtime.** Multi-year, post-v2.0 per the MMO RFC.
- **Bytecode VM dispatch-loop redesign.** Phase 8.5 / 29 honest deferral. Phase-sized; re-enters as its own perf phase.
- **3D loose-grid spatial partition / SAH-BVH / occlusion culling proper / LOD smooth transitions.** All Phase 32 follow-on items; each ≥ 1 phase.
- **Streaming asset cache (`world.cache`).** Phase 32 v2 ergonomic feature; defer.
- **`save SaveSlot:` typed-field declarations (Path A).** The v1.0.1 Session 5 spec included `var hp: int = 100` field declarations creating save-store-backed globals. That requires a new variable-binding mechanism in eval + VM + type checker — phase-sized, crosses the v1.0.2 "no semantic change" scope filter. Re-enters as a dedicated phase under v1.1. The Path B anchor-only block in Session 1 lands the structural deferral closure; the typed-field deferral is acknowledged here.
- **`entity X: lod = [...]` / `entity X: rollback = true` parser sugar.** Cut from v1.0.2 at the planned spike — see Session 3 entry above. Re-enters in v1.1 alongside the Phase 32 wgpu render integration and the Phase 37 eval-side rewind engine. Designing the sugar against working runtimes is cleaner than designing it against absent ones.
