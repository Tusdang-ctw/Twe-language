# web3d-M9 plan — asset pipeline parity

**Opened:** 2026-10-04 (after M8 closed; M0–M8 all done)
**Line:** creation-parity (M8–M12) — see [the roadmap](2026-10-04-creation-parity-plan.md). M9 ∥ M10 per the order there.
**Commit prefix:** `web3d-m9:`. Closeout: `docs/changes/<date>-web3d-m9-closeout.md`.

## The milestone, in one line

> A glTF that Three.js's `GLTFLoader` loads, Twe loads too — compressed textures and geometry included.

## Exit criteria (from the roadmap, restated)

1. **KTX2/Basis textures render.** Prefer **build-time transcode** so the runtime stays pure-Rust / wasm-safe (cut line below).
2. **meshopt** geometry loads (`EXT_meshopt_compression`).
3. **Draco** geometry loads (`KHR_draco_mesh_compression`).
4. **`KHR_materials_anisotropy`** applied (an anisotropic BRDF, not just the 16× sampler).
5. **Morph targets** sampled (currently the one `MorphTargetWeights => continue` at `render.rs:4089`, and no vertex deltas read).
6. **Multi-skin** (today `extract_skin_data` takes `doc.skins().next()` only — `render.rs:4042`).
7. **`twec asset info <file>`** subcommand + a VRAM estimate against the 512 MB budget.
8. **Studio `AssetBrowser` preview** — lands in the sibling repo `D:\IT\twe-engine` (`studio/src/components/Explorer/AssetBrowser.tsx`), not here.

**Artifact:** a demo loading a Draco + KTX2 Blender export that Three.js also loads, side by side.

**Cut line:** if a decoder is C++/wasm-hostile (Basis, Draco), transcode at **build time** and document that the runtime doesn't decode it — **never break `cargo build`**, and never add a non-pure-Rust dependency to the default runtime path. Build-time-only tools may gate behind a feature (e.g. `asset-tools`).

## Grounded current state (from the 2026-10-04 asset-path map)

- glTF import is single-skin, no-morph, no-compression: `render.rs::parse_glb_bytes` (`:3967`) → `flatten_primitive` (`:4723`) → `upload_loaded_glb` (`:4858`); native-only (play3d/physics3d), excluded from wasm32 — so the web path already consumes a pre-built runtime, which **reinforces** build-time transcode.
- Textures: `image` 0.25 (png/jpeg/hdr) → CPU RGBA8 → `material.rs::upload_rgba` (`:696`). No compressed `TextureFormat::Bc*`/`Etc2`/`Astc` used for assets.
- Material extensions: raw-JSON reader in `material.rs` (~`:358`), 7 `KHR_materials_*` + `KHR_texture_transform` handled; **anisotropy absent**. 4 `EXT_SLOTS`, 12 `ROLES`.
- Skin: `extract_skin_data` (`render.rs:4037`), `MAX_JOINTS = 128`, LBS in WGSL (`:773`). Joints/weights set 0 only.
- CLI: flat match in `cli.rs::run` (`:68`); add `"asset" => process::exit(handle_asset(...))` + a `USAGE` line; sub-sub-command pattern per `handle_bench` (`:795`). `twec info` (`:433`) is bundle provenance, unrelated.
- Build/bundle copy assets raw (`build.rs::walk_assets` `:547`; only optional zstd in `bundle.rs`).

## Sessions

Self-contained engine features first (low risk, each ships a demo), compression last (crate/transcode decisions), artifact + closeout to end.

1. **`twec asset info <file>`** — glTF/glb + image inspector. Meshes/primitives, vertex+index counts, materials and which KHR extensions each uses (incl. anisotropy), textures (dimensions + source format + sRGB), skins (count → flags multi-skin), morph targets present (count), and compression detected (`EXT_meshopt_compression` / `KHR_draco_mesh_compression` from extension lists; KTX2/basisu from image MIME + magic). Ends with a **VRAM estimate vs the 512 MB budget**. No GPU, no rendering — pure inspection. This tool *enumerates the M9 gap* and seeds every later session (it reports "Draco: present (not loaded)" until session 6 closes it). Tests on committed fixtures (`examples/assets/triangle.glb`, `survive3d/assets/hero.glb`).
   **DONE 2026-10-04.** `src/asset_info.rs` (GPU-free, wasm-safe, via `gltf::Gltf::from_slice` + header-only image reads + a manual KTX2 header parse); `twec asset info [--json] <file>` in `cli.rs`; exit 1 when over the 512 MiB VRAM budget. Gaps are flagged with their session pointers (e.g. "KHR_materials_anisotropy present — rendered isotropically (M9 session 4)"). `tests/asset_info.rs` (5) + 3 unit tests; native + wasm32 clippy clean. Verified on the hero (skin/2 anims/PNG), AnisotropyBarnLamp (anisotropy+clearcoat+transmission flagged, 85.7 MiB VRAM), DamagedHelmet (5 JPEGs, 107.2 MiB).

2. **Morph targets** — read POSITION/NORMAL/TANGENT morph deltas in `flatten_primitive`; handle the skipped `MorphTargetWeights` channel; a morph-weight UBO + WGSL blend across the lit/depth/shadow pipelines; cap N targets (budget like `MAX_JOINTS`). Ships a morphing demo (a committed procedurally-authored or small Khronos morph glb).
   **DONE 2026-10-04.** Chose **CPU pre-blend** over a morph UBO + WGSL: deltas are read in `flatten_primitive` (world-transformed as directions for unskinned prims, local for skinned), stored aligned to the vertex buffer in `MorphData`; weights come from `mesh.weights` + the `MorphTargetWeights` channel (`extract_morph_tracks`, keyed by clip name) sampled in the per-frame loop; `blend_morph` recomputes `base + Σ wᵢ·deltaᵢ` and re-uploads the (now `COPY_DST`) vertex buffer only when weights change — so **every** pipeline variant (lit/depth/shadow/AO) picks it up with zero shader edits, and morph correctly applies before skinning. Bound radius grows by the worst-case delta so a morphing mesh isn't wrongly culled. Fixture `examples/assets/morph_quad.glb` (`tests/gen_morph_quad.rs`); demo `examples/morph_demo.twe`. Tests: `blend_morph` + `sample_morph_weights` + `parse_glb_captures_morph_targets_and_track` (render.rs) + the fixture/asset-info test; native + wasm32 clippy clean; 557 lib tests pass. **Scope:** per-mesh weights (not per-instance), first morphing node per document — per-instance/per-node routing deferred. **GPU/visual verification of the morph animation is a maintainer step** (no GPU here).

3. **Multi-skin** — generalize `extract_skin_data` to all `doc.skins()`; per-node skin index; per-draw skin selection in `upload_loaded_glb` + the frame upload. Ships a two-skin demo.
   **DONE 2026-10-04.** The joint group is bound once per mesh across 6+ draw passes, so rather than rewire per-submesh binding (high-risk, blind), all skins are **concatenated into one joint array** (`build_combined_skins`) and each skinned primitive's `JOINTS_0` is offset by its skin's base (`flatten_node`/`flatten_primitive` thread `skin_base`); `compute_skinned_joint_matrices` fills the combined array. One bind group still serves every submesh — zero draw-site changes. Bounded by `MAX_JOINTS=128` total (an overflowing skin is dropped + logged). Headless test `parse_glb_combines_multiple_skins` (2-skin glb → combined `[2,3]`, mesh B offset to joint 1); the single-skin hero still renders (survive3d headless-GPU tests 4/4). Native + wasm clippy clean. **Deferral:** >128 combined joints, and per-submesh skinned/unskinned mixing, stay out of scope; visual confirmation of a 2-character scene is a maintainer step.

4. **`KHR_materials_anisotropy`** — read the extension (anisotropyStrength, anisotropyRotation, anisotropyTexture) into a new role/slot; tangent-frame anisotropic GGX in WGSL. Validate on the `AnisotropyBarnLamp` bench scene (Twe is 0.0513 there isotropically — real anisotropy should hold or improve, and visibly match the reference highlight shape).
   **DONE 2026-10-04.** Data path: `ROLE_ANISOTROPY`, `Extensions.anisotropy_strength/_rotation`, the `KHR_materials_anisotropy` branch in `read_extensions`, and `MaterialUniform.ext` grown 6→7 vec4 (ext[6] = strength, cos, sin). WGSL: `Surface`/`Lobes` gain the anisotropy frame; `d_ggx_aniso` + `v_smith_ggx_aniso` (Filament/Khronos) drive the direct lobe, and the IBL reflection bends toward the anisotropy frame (the visible effect, since the bench scenes are environment-lit). **Gated behind strength > 0**, so isotropic materials are byte-identical. Tests: `anisotropy_extension_read_from_gltf` + the `MaterialUniform` size assertion + the existing `main_shader_parses_and_validates` naga check now cover it; survive3d headless-GPU render 4/4 confirms the enlarged uniform binds; native + wasm clippy clean. **Visual parity + the AnisotropyBarnLamp ꟻLIP re-score are a maintainer GPU step** (the formula is a standard one; exact match to the Khronos reference is unverified here).

**ARCHITECTURE DECISION (sessions 5-7, locked with the maintainer 2026-10-04):** the compression trio lands as **build-time transcode behind an `asset-tools` cargo feature**, not runtime decode. `twec asset transcode <in> [-o out]` decodes into a plain `.glb` the runtime loads unchanged; the decoder crates (draco-gltf, ktx2, basisu, meshopt) compile only under the feature and are referenced solely from `src/asset_transcode.rs`, so the default runtime and the wasm32 browser build stay pure-Rust and wasm-safe (the cut line). The research flagged every candidate crate as new/unproven, which is a further reason to keep them off the default path.

5. **meshopt geometry** — `EXT_meshopt_compression`.
   **DONE (honest deferral) 2026-10-04.** The meshopt 0.6 crate exposes `decode_vertex_buffer`/`decode_index_buffer` but **not** the inverse vertex filters (octahedral/quaternion/exponential) nor index-sequence decode. gltfpack routinely filters normals/tangents, so decoding without them would silently produce corrupt geometry — a Principle-3 "no silent footgun" violation. Rather than ship that, `meshopt_pass` **errors clearly** and names the fix (port the three filters, or an upstream crate that exposes them). Draco covers the compressed-geometry need today. Test: `meshopt_pass_errors_honestly`.

6. **Draco geometry** — `KHR_draco_mesh_compression`.
   **DONE 2026-10-04.** `draco_pass` uses the pure-Rust `draco-gltf` 0.5 (`import_slice` → `decompress_in_place` → `to_bytes(GlbV2)`), then strips the extension from `extensionsUsed`/`Required` + each primitive and **prunes the orphan Draco accessors** `decompress_in_place` leaves behind (remapping references across meshes / morph targets / skins / animations), so the strict runtime loader accepts the output. Verified end-to-end: `transcodes_draco_box_to_plain` decodes the committed Khronos Box-Draco and asserts the vertex count matches the plain `Box.glb`.

7. **KTX2 / Basis textures** — `KHR_texture_basisu`.
   **DONE 2026-10-04.** `ktx2_pass` transcodes each KTX2 image (ETC1S/UASTC) to RGBA8 via the pure-Rust `basisu` 0.1 transcoder, re-encodes PNG with the `image` crate, repoints the texture's `source` and drops `KHR_texture_basisu`. (RGBA8 PNG rather than GPU-compressed BCn keeps the runtime unchanged; a BCn-upload path for VRAM savings is a follow-on.) Verified: `transcodes_ktx2_texture_to_png` embeds a real 32×32 Basis-UASTC KTX2 (CarConcept `Rib_N.ktx2`) in a minimal glb, transcodes it, and confirms a 32×32 PNG that the runtime loads.

8. **Build pipeline + VRAM budget** — enforce/warn on the 512 MB budget + surface compression.
   **DONE 2026-10-04.** `build::audit_assets` inspects every bundled glTF/image during `twec build`: it sums estimated VRAM against the 512 MiB budget and warns about any asset using a compression extension the runtime can't load (via `asset_info::compression_extensions`, which reads raw `extensionsUsed` so it catches even Draco files the strict loader rejects), pointing at `twec asset transcode`. Warnings only — never fails the build. Test: `audit_warns_about_draco_and_vram`. The Studio `AssetBrowser` 3D preview lands in the `twe-engine` repo and consumes `twec asset info --json`.

9. **Parity artifact + closeout** — a Blender export with Draco + KTX2 that Three.js also loads, rendered in Twe side-by-side with three; `docs/changes/<date>-web3d-m9-closeout.md` against these exit criteria.
   **Closeout written 2026-10-04.** The transcode is verified against real Khronos compressed samples (stronger + reproducible vs a hand-made Blender export); the side-by-side-with-Three.js render + the Blender round-trip are the maintainer GPU step, documented in the closeout.

Sessions may merge/split as the work reveals itself (the compression trio 5–7 is the risk; 1–4 are self-contained). Order: 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9.

## Rules (inherited)

Clippy clean for native + `wasm32` + `-p twe-web`; `cargo test` green. Every session ships a runnable artifact; docs updated in the same commit (`docs/06` §7 for new builtins/subcommands, this note's session list checked off). Nothing is "closed" until its exit criteria are met. No non-pure-Rust crate on the default runtime path — build-time/`asset-tools`-gated only.
