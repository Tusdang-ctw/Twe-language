# 2026-04-30 — v0.2 session 2c: VM nested-block wait parity

## Status: shipped. Third of three sessions on the function-body `wait` track. Brings the bytecode VM to parity with session 2a (resumable `if` / `while` blocks). Function-body `wait` on the VM remains deferred — it requires a multi-frame fiber save (`Vec<BcFiberFrame>` on `BcInstance`) which is its own engineering pass.

## Background

Sessions 2a and 2b lifted the tree-walker's "wait only as a direct child of on_entry" limit:

- **2a**: `wait` works inside `if` / `elif` / `else` / `while` blocks at the top of a state's `on_entry`. Implemented via a per-Instance `entry_resume_path: Vec<PathEntry>`.
- **2b**: `wait` works inside a function called from `on_entry`. Implemented via a per-Instance `fiber_frames: Vec<Frame>` (state-entry + function frames).

The bytecode VM kept the original Phase 5 single-frame mechanism: `BcInstance::entry_resume_function` + `entry_resume_ip` save one (chunk, IP) pair. Anything beyond a flat top-level wait surfaced a compile-time error.

Session 2c gets the VM to 2a-parity: nested-block wait inside on_entry now compiles and runs correctly. Function-body wait stays deferred — it would need a multi-frame save of the call stack plus the value-stack slice for each frame, all preserved across the suspension.

## What ships

### Compiler: `allows_wait` flag on `Frame`

`src/compiler.rs`:

- New `Frame::allows_wait: bool`. Default `false`.
- `compile_on_entry` sets it `true` on the on_entry frame before pushing.
- `emit_stmt`'s `Stmt::Wait` arm now checks the flag. When set, emits `OP_WAIT` (with a const-folded duration when literal). When unset, errors with the usual "wait is only supported..." message.
- `compile_on_entry` no longer needs its own pre-walk: the flagged `emit_stmt` handles every wait reachable through nested `if` / `while` / etc. without special-casing the top level.

This is the only structural change on the compile side — every other frame kind (function bodies, every clocks, on_update, predicate hooks, scripts) leaves `allows_wait` at `false`, so wait inside them keeps producing the same error.

### Runtime: save the value stack at suspension

`src/bytecode.rs`:

- `BcInstance` gains `entry_resume_locals: Vec<Value>` — the saved slice of the value stack from `slot_base + 1` to top at suspension.

`src/vm.rs` `OpCode::Wait`:

- Before truncating the stack, snapshots `self.stack[slot_base + 1..]` into `entry_resume_locals`. Slot 0 is the receiver (re-pushed by resume from the scene Rc), so we only need to save user-visible locals + temporaries above it.
- Without this, locals declared inside the body (`var i = 0` before a `while i < 3:` containing a wait) were lost at suspension. The pre-2c behavior worked only when no live locals existed — why session 2a's machinery was tree-walker-only.

`src/vm.rs` `resume_state_entry`:

- After pushing the receiver, pushes the saved locals back onto the stack. Subsequent `OP_GET_LOCAL` instructions read the right values.

`src/vm.rs` `enter_state`:

- Clears `entry_resume_locals` alongside `entry_resume_function` / `entry_resume_ip`. Entering a state always restarts on_entry from the top.

### Tests

3 new VM tests in `src/vm.rs::tests`, plus 1 flipped:

- **Flipped:** `vm_wait_inside_if_in_state_body_is_a_compile_error` → `vm_wait_inside_if_in_state_body_resumes`. Same source, different expectation. Pins the new capability.
- `vm_wait_inside_while_in_state_body_resumes` — three iterations of an inner while across four frames. Exercises both the `OP_WAIT` save/restore *and* the stack-slice save (the loop counter `i` is a local).
- `vm_wait_inside_elif_resumes_same_arm` — pin elif-arm preservation. The bytecode compiler emits separate jumps per arm; the saved IP lands inside the chosen arm's body, not back at the elif chain's head.

Plus the existing `vm_wait_outside_state_body_is_a_compile_error` carries through with an updated comment noting that *function-body* wait specifically remains deferred.

## Not in scope

- **Function-body wait on the VM.** Requires a multi-frame fiber save: at OP_WAIT, capture the entire `self.frames` Vec along with each frame's value-stack slice. Restore on resume by re-pushing the values in order then re-pushing the frames. The trick is the value stack is shared across frames — a clean save needs to record the bottom-most slot_base at suspension and copy from there. Tracked in `notes/future-phases.md` as a follow-on session.
- **`for` body wait on the VM.** Same multi-frame issue plus iterator-state preservation. Tree-walker doesn't support this either yet (deferred from 2a/2b); both backends pick it up together when it lands.
