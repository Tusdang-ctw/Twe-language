# 2026-04-30 — v0.2 Phase 8.5 session 8a: TaggedValue module

## Status: shipped. First of nine sessions in the NaN tagging + tracing GC migration (`docs/08-nan-tagging.md`). Standalone foundation — the module compiles, ships round-trip unit tests, but is NOT yet used by any other code path. Sessions 8b–8i wire it through the rest of the codebase.

## Background

`docs/08-nan-tagging.md` (the design doc shipped with the v0.2-v1.0 roadmap) lays out the byte layout and migration sequence for replacing the existing `enum Value` representation with a NaN-tagged 64-bit slot. The migration is staged across 9 sessions because 746 `Value::` sites span the codebase (eval.rs 3000 lines + vm.rs 3766 lines + stdlib.rs 1992 lines); rolling the whole thing into one session would either skip GC or break the migration mid-flight.

This session — 8a — is the standalone foundation. New module, no migrations yet. Round-trip tests pin every encoding decision so subsequent sessions can build against a stable bit layout.

## What ships

### `src/tagged_value.rs` — new module

Bit layout follows *Crafting Interpreters* Ch. 30:

```
63       62..52      51   50..48     47..0
[sign]   [exp 11b]  [Q]  [tag 3b]  [payload 48b]
```

For tagged values, bits 62..51 are all 1 (QNaN signal). Bits 50..48 carry the 3-bit type tag. Bits 47..0 carry the payload.

| Tag | Type     | Payload                            |
|-----|----------|------------------------------------|
| 000 | Float NaN| `f64::NAN` canonical pattern       |
| 001 | Nil      | unused                             |
| 010 | Bool false | unused                           |
| 011 | Bool true  | unused                           |
| 100 | Int      | i48 (sign-extended on read)        |
| 101 | Str      | `Rc<HeapObject>` ptr → `String`    |
| 110 | Obj      | `Rc<HeapObject>` ptr → all other heap variants (session 8b) |
| 111 | reserved | (future: smallfloat32 / builtin-id) |

Floats are stored as raw IEEE 754 bits. `f64::NAN` canonicalizes to tag 0 so it's distinguishable from our tagged Nil/Bool/Int.

### Public API

```rust
pub struct TaggedValue(u64);

// Constants
TaggedValue::NIL
TaggedValue::TRUE
TaggedValue::FALSE

// Constructors (infallible)
TaggedValue::from_bool(b: bool)
TaggedValue::from_int(n: i64)        // i48 fast path; i64 over-range loses precision in 8a
TaggedValue::from_float(f: f64)       // canonicalizes NaN
TaggedValue::from_string(s: String)
TaggedValue::from_borrowed_str(s: &str)

// Predicates
v.is_nil()
v.is_bool()
v.is_int()
v.is_float()
v.is_number()                         // int OR float
v.is_str()
v.is_obj()

// Extractors (debug_assert on type mismatch)
v.as_bool() -> bool
v.as_int() -> i64
v.as_float() -> f64
v.as_string() -> String

// Migration shim (session 8f deletes this)
TaggedValue::from_legacy(&Value)
v.to_legacy() -> Value
```

### Refcount-managed Clone + Drop

`TaggedValue` is *not* `Copy` because pointer-tagged variants own an `Rc<HeapObject>`:

- `Clone`: heap variants `Rc::increment_strong_count`; immediates copy the u64 directly.
- `Drop`: heap variants reconstruct the `Rc` via `Rc::from_raw` so the matching decrement fires.

Tests pin the round-trip: cloning a `TaggedValue::from_str("shared")` three times and dropping two of the clones leaves the third readable.

### Heap representation (skeleton)

```rust
pub enum HeapBody {
    String(String),
    // session 8b populates the rest: List, Tuple, Object, Quantity,
    // Range, Function, BcFunction, Class, BcClass, Builtin, Instance,
    // BcInstance.
}

pub struct HeapObject {
    pub body: RefCell<HeapBody>,
    // session 8b adds: header: HeapHeader (mark bits, body_kind discriminator).
}
```

Session 8a covers `HeapBody::String` only — enough to exercise the pointer-tagging codepath. Session 8b expands the enum and migrates the rest of the existing `Value` variants.

### Unsafe scoping change

`Cargo.toml` lint eased from `unsafe_code = "forbid"` to `"deny"`. `#![allow(unsafe_code)]` scoped to `src/tagged_value.rs` only. Every other module stays under the project-wide deny.

This is a real architectural decision flagged in `CLAUDE.md` §"What is locked": NaN tagging fundamentally requires bit-level pointer manipulation (`Rc::into_raw` / `Rc::from_raw`) that Rust's safety model can't express. Adding `unsafe` anywhere else needs an explicit roadmap entry.

### Tests

13 new unit tests in `src/tagged_value.rs::tests`:

- `nil_round_trip` / `bool_round_trip` — immediate-tag round-trip + cross-predicate exclusion.
- `int_round_trip_small` — common cases (0, ±1, ±42, ±1M).
- `int_round_trip_i48_extremes` — `(1 << 47) - 1` and `-(1 << 47)`.
- `float_round_trip` — 0, ±1, π, ±1e100, ±∞.
- `float_nan_canonicalizes_and_remains_a_float` — NaN passes `is_float`, doesn't collide with Nil tag.
- `string_round_trip` / `empty_string_round_trips` / `unicode_string_round_trips` — heap-tagged encode/decode.
- `clone_bumps_refcount_and_drop_balances` — pin the manual Clone/Drop semantics.
- `predicates_partition_correctly` — every value reports exactly one `is_*` category.
- `is_number_covers_int_and_float` — pin the convenience predicate.
- `legacy_shim_round_trips_primitives` — Nil/Bool/Int/Float/Str round-trip through `from_legacy` → `to_legacy`.

All 13 pass. The full sweep is **488 tests** (327 in lib including 13 new + integration tests).

## Not in scope

This session ships **only** the standalone module. The following ride 8b–8i:

- **8b**: Expand `HeapBody` to cover List, Tuple, Object, Quantity, Range, Function, BcFunction, Class, BcClass, Builtin, Instance, BcInstance. Add `HeapHeader` (mark bits + body_kind discriminator).
- **8c**: Migrate the bytecode VM's value stack + dispatch loop to use `TaggedValue`.
- **8d**: Migrate the tree-walker (`Env::bindings`, `Instance::fields`).
- **8e**: Migrate stdlib + save module (~205 + 87 `Value::` sites).
- **8f**: Delete the legacy `enum Value`. `Value` becomes an alias for `TaggedValue` (or fully renamed).
- **8g**: Replace Rc-based heap with a stop-the-world tracing GC heap allocator.
- **8h**: Wire roots (VM stack + globals + active_scene + fiber_frames; eval env bindings + Instance fields + fiber stacks).
- **8i**: Bench against pre-migration baseline. Tune until ≥3× speedup criterion is met.

Plus the i48-vs-i64 boxing decision lands in 8b: large integers (outside i48 range) need to box behind `TAG_OBJ` rather than truncate. 8a has the truncation path; tests intentionally don't exercise above-i48 values.
