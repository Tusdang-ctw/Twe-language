# web3d-M4 plan: `survive3d` and the Studio viewport

**Opened:** 2026-09-28
**Milestone:** web3d-M4 (plan: [`2026-09-27-web3d-pivot.md`](2026-09-27-web3d-pivot.md)). M7 (graphics) follows M4 ([M7 plan](2026-09-28-web3d-m7-graphics-beyond-threejs.md)).

**Exit criteria (from the pivot plan):**
- a playable 10-minute run of `survive3d` published on itch.io (web);
- 10 consecutive full runs with no crash or GC-stress failure;
- Studio plays the game in its own viewport, with hot reload.

## Method

The same as M3: build the game on today's engine, and let what it hits decide the engine work.

## Session 1 (2026-09-28): the game runs

**`examples/survive3d/main.twe`** is `survive_beta`'s design in 3D:
- **Enemies:** slime, bat, skeleton, boss.
- **Weapons:** auto-aimed bolt, orbiting blades, aura.
- **Pickups:** XP gems with a magnet.
- **Progression:** waves, a boss every fifth wave, a level-up picker, pause, game over and restart.

Everything is an entity with a `look:`. The per-state HUD and menus use `text()` / `rect()`. `tests/survive3d.rs` plays a run headless through the 3D render path with scripted input: fight, level up and pick, pause and resume, die, restart. `tests/kernel_render.rs::survive3d_frame_renders` renders a frame on the GPU.

**Engine gaps the game found, all fixed this session:**
1. **Scene state `on render():` was ignored in 3D.** Only the top-level handler ran, so per-state HUDs and menus couldn't draw. `eval::render_scene_state` is now shared by the 2D and 3D paths.
2. **The web shell reported 11 keys.** `host3d::KEY_CODES` is now the one table (letters, digits, F-keys, modifiers) for both shells, and a test pins the native table to it.
3. **Script colours were fed to lighting as if linear.** Tints are sRGB, as authors pick them; the kernel now decodes them, so dark reads dark and saturated reads saturated. Every 3D scene looked washed out before; Three.js does the same decoding.
4. **`math.clamp`** was documented in `docs/06` §7.2 but never installed.

## Remaining sessions (in order)

1. **Audio on the web.** `sound.*` is silent in the browser today (`env.js` stubs macroquad's audio). The fix is WebAudio playback from the web shell, and shots, hits, level-up and the boss get sounds.
2. **Saves on the web** (`save.*` to localStorage: best wave and time) and **pause on tab-away** (`document.visibilitychange`).
3. **The input-command stream.** All input becomes per-tick commands through one queue, so replays (`replay.rs`) record and play back on the web too. This is the net-ready hook.
4. **Mouse and gamepad on the web.** The level-up picker becomes clickable; gamepads come through the browser Gamepad API.
5. **Asset pipeline for the slice.** At least one real `.glb` character (animated, via the existing skinning), content-hashed runtime files in `twec build --target web` (the M3 stale-cache finding), and a preload screen.
6. **Soak.** 10 consecutive scripted 10-minute runs, native and wasm, including under `TWE_GC_STRESS`.
7. **Studio viewport** (`D:\IT\twe-engine`): the web build in the Tauri WebView, served over a `twe://` protocol, with hot reload on save. Falls back to a browser tab where WebView2 lacks WebGPU.
8. **The itch.io build** (published by the maintainer), then the closeout.
