## The task set

There are 60 tasks with 362 checks, each with a Twe and a Python reference solution and twin checks. All 60 validate in both languages: every check is failed by some running mutant of its solution.

| | Tier 1 | Tier 2 | Tier 3 | All |
|---|---:|---:|---:|---:|
| New | 9 | 23 | 18 | 50 |
| Edit | 3 | 5 | 2 | 10 |

**Edit tasks** hand the model a working v0 program and ask for one change: sprinting, pausing a countdown, coins that respawn, a door that closes itself, a night mode for the traffic light, automatic reloading, a double jump, a shield, a cap on spawns, a snake that speeds up. They measure reading and changing existing code through the SEARCH/REPLACE protocol, which is most of how LLMs are used on real projects. Every starter fails its task.

**The new tasks are harder than v0:**
- **Several interacting systems:** orbiting blades with per-enemy damage cooldowns, a guard with a vision cone, a tower choosing the enemy furthest along a path, chain lightning, homing missiles, breadth-first pathfinding, rewinding time.
- **Exact rule-following:** combo input buffers, stack-filling inventories, a leaderboard, a quest chain.

**How the check values were set:**
1. The input script and expected values were derived from the task text.
2. Both reference solutions were probed through the grader. They are independent implementations in two languages.
3. Every disagreement was resolved by re-deriving from the text. In each case the derivation had been wrong, not the solutions. Examples: a shield hit at tick 150 is still blocked; a second rewind reaches back to tick 58; the enemy the player walks through survives the orbiting blades.

**Two specs were changed** because an event landed exactly on a tick boundary, where floating-point drift decided the outcome:
- `night_spawns` spawns every 1.5 s, where every 1 s put the 11th spawn on dawn;
- `maze_path`'s last check moved off a step tick.

## Infrastructure (bench v1)

- **Canary.** `bench::CANARY` (BIG-bench style, GUID `35ea5552-…`) is in every `task.toml` and on the first line of every reference solution. It is never in anything sent to a model (`task.md`, the interfaces, starters). `tests/bench.rs` checks both.
- **Comparability.** `run.json` records the hashes of the system prompt and the task set, and a run directory refuses a resume when either changed. `BENCH_VERSION` is `v1`.
- **A contamination sign.** A sample whose final program is nearly the reference solution (character-trigram Jaccard ≥ 0.9, ignoring comments and layout) is flagged in `samples.jsonl` and reported as a rate. It is flagged, not excluded.
- **Edit tasks are scored separately** in the summary.
- **A hidden set.** `--tasks-root DIR` runs a task set kept outside the repository.
- **Tests.** `every_committed_task_is_sound` checks files, the canary, solution passes and starter fails for all 60 tasks in 2 s. The full mutant validation, about 4 minutes, is `every_check_is_caught_by_a_mutant` (`-- --ignored`).

## The second pilot

A Claude subagent wrote all 40 new tasks from the task text alone, with the starters for edit tasks, and without seeing the solutions or checks. **All 40 of its programs pass.** It listed about 40 points where the text left a choice open (tick order, `<` against `<=`, whether a step happens on the press tick), and the checks hold under its choices.

**Two texts were clarified:**
- `traffic_night`'s interface now lists "off";
- the guard's cone is "at most 60 degrees to either side".

**What it found about Twe** (fixed before any measurement; no run had happened):
- **A second top-level `on update` silently replaced the first.** `twec verify` now reports it (`duplicate-handler`). No program in the repository had one.
- **The primer now says** that integer division truncates (`7 / 2` is 3), and in what order a tick runs: the top-level `on update`, then each entity's `update`, including one spawned that tick. Both were checked before being written down.

**What it got wrong:** it reported `sphere` and `cube` missing from the stdlib manifest. They're there.

**What it confirmed:** `spawn` returning no handle is the most awkward pattern in the language. Two tasks need it worked around: `bullet_pattern` and `damage_numbers`.

## The `nil` literal

`docs/06` §2.5.3 specifies `nil`, but the name was never bound, and `inventory_stacks` hit it. The stdlib now binds it ([pre-measurement fixes](2026-10-01-web3d-m5-pre-measurement-fixes.md)).
