# 2026-04-30 — v0.2 session 7: VM function-body `wait`

## Status: shipped. Closes the deferred half of session 2c — the bytecode VM now handles function-body `wait` to full parity with the tree-walker (session 2b). The only remaining wait-context gap is `for`-body wait, which is deferred on both backends since it needs iterator-state preservation.

## Background

Session 2c brought the VM to "wait inside `if` / `elif` / `else` / `while` blocks at the top of state on_entry" parity (matching tree-walker session 2a). It explicitly deferred function-body wait because the VM's then-current OP_WAIT only saved a single `(chunk, IP, locals)` triple. A function called from on_entry pushes a new VM frame; the wait inside that frame would corrupt the resume.

This session reifies the VM's call stack on suspend: the entire frame chain from the state-entry frame down to the current top is captured, along with the value-stack slice covering all those frames' locals + temporaries. Resume replays the chain in one go.

## What ships

### `BcInstance` data model

`src/bytecode.rs`:

```rust
pub struct BcFiberFrame {
    pub function: Rc<BcFunction>,
    pub ip: usize,
    pub slot_base_offset: usize,
}

pub struct BcInstance {
    // ...
    pub fiber_frames: Vec<BcFiberFrame>,  // was: entry_resume_function + entry_resume_ip
    pub fiber_stack: Vec<Value>,           // was: entry_resume_locals
    pub entry_wait_remaining: f64,
}
```

`fiber_frames[0]` is the bottom of the fiber (the state-entry frame); deeper indexes are nested function calls. `slot_base_offset` is recorded relative to the bottom frame's `slot_base` so the saved frames can be replayed at any later VM stack offset.

### VM state tracking

`src/vm.rs::VM`:

```rust
state_entry_frame_depth: Option<usize>,
```

Set by `enter_state` *before* invoking `state.on_entry`; cleared after. `OP_WAIT` reads it to know how much of the call stack to capture (everything from `self.frames[depth]` to top).

This is also the runtime gate: `wait` outside a state-entry call chain becomes a runtime error here, replacing the prior compile-time `allows_wait` flag. The error message ("`wait` is only valid in a state's on_entry body or a function called from there") points users at `--vm tree` for non-on_entry contexts.

### `OpCode::Wait` rewrite

Previously: pop duration → save current frame's `(function, ip, locals)` → truncate one frame.

Now:
1. Pop duration.
2. Verify `state_entry_frame_depth.is_some()` — error if not.
3. Walk `self.frames[entry_depth..]`, recording each frame as a `BcFiberFrame` with `slot_base_offset` relative to the bottom.
4. Slice `self.stack[bottom_slot_base..]` into `fiber_stack`.
5. Truncate `self.frames` and `self.stack` back to before the state-entry call.
6. Push synthetic Nil and unwind via `Return`-style logic.

### `resume_state_entry` rewrite

Previously: push receiver + locals → push one frame → dispatch.

Now:
1. Take the saved `fiber_frames` + `fiber_stack` off the BcInstance.
2. Push the entire `fiber_stack` onto `self.stack`. Bottom is the on_entry frame's slot_base.
3. Push each saved frame back, recovering absolute slot_base by adding `slot_base_offset` to the new bottom-of-fiber.
4. Set `state_entry_frame_depth` so a deeper-still wait during resume can suspend correctly.
5. Dispatch.

### Compiler changes

`src/compiler.rs`:

- Removed `Frame::allows_wait`. The runtime gate replaces it.
- `Stmt::Wait` always emits `OP_WAIT` regardless of which compiler frame contains it.
- `compile_on_entry` collapses to `compile_state_body` — no on_entry-specific compile logic remains. (The function name stays because future on_entry-specific work, e.g. `on enter:` / `on exit:` hooks per Snake's NP9, will route here.)

### Tests

4 new tests in `src/vm.rs::tests`, plus 1 flipped:

- **Flipped:** `vm_wait_outside_state_body_is_a_compile_error` → `vm_wait_outside_state_body_is_a_runtime_error`. Same source (`function pause(): wait 0.5s; pause()`), same intent ("wait outside on_entry must be flagged"), but the failure now surfaces at runtime via the `state_entry_frame_depth` gate rather than at compile time.
- `vm_wait_inside_function_called_from_state_entry_resumes` — basic two-frame fiber.
- `vm_wait_inside_function_inside_if_resumes` — the function call sits inside an if-then; verify the `if`-frame layout doesn't confuse the multi-frame save.
- `vm_two_sequential_waiting_calls_run_in_order` — back-to-back wait-bearing calls; three suspend cycles across three frames.
- `vm_function_calls_function_with_wait` — three-frame fiber at suspension time (state-entry + outer + inner). Resume drains innermost-first.

`run_err` test helper added: runs a program and returns the runtime-error message (for tests that expect failure rather than compile rejection).

## Not in scope

- **Method-body wait on the VM** — same shape as function-body wait but `BcFiberFrame` would need to carry method receiver context too. Follow-on; tree-walker also defers (per session 2b's "Not in scope").
- **Call-as-expression wait** (`let x = f()` where `f` waits). Same deferral as the tree-walker.
- **`for`-body wait** — needs iterator-state preservation across both backends. Follow-on.
- **`every` / `on update` / `dialogue` wait** — these contexts don't push state-entry frames, so the runtime gate rejects them by design. `dialogue` will get a per-dialogue scheduler in Phase 9.
