# 2026-04-29 — v0.2 session 1: `.glb` mesh import

## Status: shipped. First v0.2 work-track session, opened the same day Phase 6 closed (`docs/changes/2026-04-29-phase-6-closeout.md`). Runs in parallel with Phase 7 (v0.1 release prep).

## Background

Phase 6 closed with `mesh()` and `.glb` import explicitly listed as v0.2 carry-overs. Without them, every `twec play3d` scene is bounded to cubes and procedurally-generated spheres. Real game content needs arbitrary meshes; this session unblocks that.

The crate-choice conversation was short: the `gltf` crate (1.4) is pure-Rust, well-maintained, and used by Bevy. `default-features = false` skips the texture-decoding stack we don't yet need; `["import", "utils"]` gives us `gltf::import` + the `Reader` API for accessor walking.

## What ships

### `Primitive::Mesh(u32)` — interned-path mesh tag

`src/value.rs`:

- `Primitive::Mesh(u32)` joins the existing `Cube` / `Sphere` variants. The `u32` is an id assigned by `Env::intern_mesh_path`.
- `Env::mesh_paths: Vec<String>` registry. Linear scan find-or-insert; a Twe scene rarely uses more than a handful of distinct meshes.
- `Env::intern_mesh_path(path)` returns the stable id; `Env::mesh_path(id)` reverse-looks-up.

The `Primitive` enum keeps `Copy + PartialEq + Eq + Hash` because the payload is a `u32` — no behavior changed for cubes / spheres.

### `mesh(path:, at:, color:, size:)` builtin

`src/stdlib.rs::mesh_impl`. Same call shape as `cube` / `sphere` plus a leading string path:

```twe
mesh("examples/assets/triangle.glb",
    at: vec3(0, 0, 0), color: color.red, size: 1.0)
```

Only valid inside `on render():` (`require_render` guards). Path is resolved against the working directory.

### Lazy GPU upload + per-mesh draw call

`src/play3d.rs`:

- `GpuMesh { vertex_buffer, index_buffer, index_count, index_format }` — per-mesh GPU resources.
- `RenderState` gains `mesh_cache: HashMap<u32, GpuMesh>` and `mesh_load_failures: HashSet<u32>`.
- Each frame's `render()` walks the queue, finds unique mesh ids not yet on GPU, calls `load_and_upload_mesh` for each. Failures (path doesn't exist, bytes aren't a valid `.glb`, no POSITION accessor) print one line to stderr and add the id to `mesh_load_failures` so subsequent frames skip silently.
- The render pass partitions the queue per primitive — cubes / spheres / per-mesh-id groups — into the shared instance buffer with disjoint ranges, then issues one `draw_indexed` per group.
- Hot reload clears both `mesh_cache` and `mesh_load_failures`. The new env's `mesh_paths` indices are independent of the old env's, so cached entries by id are stale; clearing also picks up on-disk `.glb` edits.

### `.glb` decode

`load_glb(path) -> Result<(Vec<Vertex>, Vec<u32>), String>` reads the file and forwards to the inner `parse_glb_bytes(&[u8])` helper. The split exists for testability — tests build minimal `.glb` byte arrays in memory and exercise `parse_glb_bytes` without filesystem touches.

Decode strategy:

- Take the first primitive of the first mesh. Multi-primitive scenes + node-graph traversal + transforms are deferred — most v0.2 user workflows export a single mesh per file anyway.
- POSITION is required; missing → error.
- NORMAL is optional; missing → fill with `[0, 1, 0]`. Mesh shades flat-bright but draws.
- Indices are optional; missing → implicit `0..N`. `into_u32()` widens u8 / u16 / u32 to u32 so the GPU pipeline only needs one branch (`IndexFormat::Uint32`).

### Tests

7 new tests in the default sweep, plus 1 `#[ignore]`-marked fixture writer:

- `value::mesh_registry_tests::intern_mesh_path_is_stable` / `mesh_path_round_trip` / `mesh_path_out_of_range_returns_none`.
- `play3d::tests::parse_glb_extracts_positions_and_indices`.
- `play3d::tests::parse_glb_fills_missing_normals_with_up`.
- `play3d::tests::parse_glb_rejects_garbage`.
- `play3d::tests::load_glb_missing_file_errors`.
- `play3d::tests::write_triangle_glb_fixture` (`#[ignore]`-marked one-shot — writes the committed `examples/assets/triangle.glb` from the in-memory minimal-glb builder; rerun on fixture changes).

The `make_minimal_glb` helper builds a hand-crafted three-vertex triangle `.glb` byte array (header + JSON chunk + BIN chunk, with min/max bounds per the glTF 2.0 spec). All other glb tests share it.

### Example

`examples/hello_glb.twe` + `examples/assets/triangle.glb` (536 bytes, generated from the fixture builder). Loads the triangle twice in differently-tinted instances alongside a cube and a sphere, with an auto-orbiting camera. Demonstrates the per-mesh instanced draw path.

## Not in scope (v0.2 follow-ons)

- **Multi-primitive scenes / node transforms / materials** — many real `.glb` files have a node graph; we currently flatten to the first primitive of the first mesh. Walking nodes + applying their TRS transforms is the next mesh-import session.
- **`.obj` loading** — different format, different crate (`tobj` is the obvious pick). Same `Primitive::Mesh` plumbing reuses cleanly.
- **Materials / textures** — we drop everything but POSITION / NORMAL on the floor. Material-driven coloring (PBR) is its own design conversation; for now the user supplies `color:` per call site.
- **Computed flat normals** — for `.glb`s exported without normals, we fall back to a constant up-vector. Computing per-face flat normals from position + indices is a small follow-on.
- **`plane()` primitive** — two triangles, same pattern as `sphere`. Probably ships next session alongside multi-primitive support.
