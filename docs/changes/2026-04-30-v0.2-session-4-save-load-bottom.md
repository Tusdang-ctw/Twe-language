# 2026-04-30 — v0.2 session 4: save / load bottom layer

## Status: shipped. First half of the v0.2 `save` work — IO + serialization for the Value subset that round-trips. The schema-block syntax + version migration ride session 5 (or later); this session's deliverable is "Twe scripts can persist data across runs *today*."

## Background

`docs/07-save-system.md` (the design doc authored alongside the v0.2-v1.0 roadmap) lays out the full save system: schema-typed `save` blocks, versioned binary format with CRC, atomic write, version migration, Steam Cloud-aware backend abstraction. That's L-sized — multiple sessions.

This session ships the layer below the schemas: `save_to(path, value)` and `load_from(path) -> value` builtins that operate on any value in Twe's *serializable subset*. Schema-block parsing, version migration, and the binary CRC format defer; the JSON-based bottom layer is enough for round-tripping game state today.

## What ships

### `src/save.rs` — new module

Bidirectional Value ↔ JSON conversion + filesystem IO.

- `encode(value: &Value) -> Result<json::Value, String>` — serializes the Value subset. Errors on functions, classes, instances, builtins, stdlib ambients (`key`, `mouse`, `screen`, `math`, etc.) with messages that point at the offending type.
- `decode(value: &json::Value) -> Value` — always succeeds; JSON's data model is a strict subset of the encodable Value surface.
- `save_to_path(path, value)` — encode + atomic write (write-to-`<path>.tmp` + rename to `<path>`). `rename(2)` is atomic on POSIX and on NTFS via `MoveFileEx(MOVEFILE_REPLACE_EXISTING)`. `fsync` defers to Phase 11 hardening.
- `load_from_path(path) -> Value` — read + parse + decode.

### Tagged round-trip for Twe-specific scalars

JSON's data model lacks Tuple-vs-List, Percent, Range, and Quantity. Rather than guess on load, those types round-trip via tagged objects:

| Twe type | JSON shape |
|---|---|
| `Tuple` | `{"__twe":"tuple","v":[...]}` |
| `Percent` | `{"__twe":"percent","v":0.25}` |
| `Range` | `{"__twe":"range","start":0,"end":10,"exclusive":true}` |
| `Quantity` | `{"__twe":"quantity","value":5.0,"unit":"kg"}` |

Plain mappings: `Nil↔null`, `Bool↔Bool`, `Int↔Int`, `Float↔Float`, `Str↔Str`, `List↔Array`, `Object↔Object` (when no `__twe` key collides — collision rejects at encode time).

### Stdlib builtins

`src/stdlib.rs` adds:

```twe
save_to(path: string, value: any) -> nil
load_from(path: string) -> any
```

The argument names are positional but `kwargs:`-callable per Twe convention: `save_to(path, snapshot)` or `save_to("slot1.save", value: snapshot)` both work.

### Tests

12 unit tests in `src/save.rs::tests` — primitive round-trip, tuple-vs-list distinction, Quantity / Range / Percent round-trip, nested Object, refusal of Function / Class / Instance / Builtin / stdlib ambient, missing-file error, invalid-JSON error, end-to-end disk round-trip.

3 integration tests in `tests/eval.rs` driving Twe source — round-trip a tuple via `save_to` → `load_from`, missing-file runtime error, function-value refusal.

### Example

[examples/save_demo.twe](../../examples/save_demo.twe) — saves a tuple of game state to `demo.save`, reads it back, prints. Output:

```
saved level/name/hp/alive/pos to demo.save
loaded:
(3, Hero, 75.5, true, (120, 200))
```

The on-disk file is plain JSON: `{"__twe":"tuple","v":[3,"Hero",75.5,true,{"__twe":"tuple","v":[120,200]}]}`.

## Not in scope (deferred to session 5+)

- **`save SchemaName:` block syntax + parser**. Lexer + AST + parser entries for the schema declaration. Deferred to keep this session shippable.
- **Schema-typed `save_to(path, as: SchemaName { ... })`** form from Example 7. Current `save_to(path, value)` is type-agnostic; the `as:` keyword-arg gates schema enforcement and lands with the schema parser.
- **Version migration** (`migrate from version N:` blocks). Needs the schema-parser hooks first.
- **Versioned binary format with CRC** per `docs/07-save-system.md` §1. Current format is plain JSON for tooling-friendliness — `cat demo.save` shows the fields. Binary + CRC ride v1.0 hardening.
- **Steam Cloud backend** (Phase 15 per the roadmap).
- **Save-rotation autosave** (`save_rotating(slot, n: 3, ...)`).
- **`fsync` after rename** for survival across power loss. Phase 11 hardening.
