# Twe v1.0.1 — Plan

> Patch-tier polish release after v1.0. Scope: 11–14 sessions of work, each shippable in one sitting per the Phase 14–16 sizing discipline. Every item makes a Vampire-Survivors-class 2D game *easier or better to ship*, not a different game. Phase-sized work (browser-3D wgpu port, MMO server runtime, console partner SDKs) stays out of `.1` by definition and remains tracked in [`05-roadmap.md`](05-roadmap.md) and the closeout notes in [`changes/`](changes/).

**Status:** **closed 2026-05-18.** 13/13 feature sessions shipped plus the Session 14 closeout. See [`changes/2026-05-18-v1.0.1-closeout.md`](changes/2026-05-18-v1.0.1-closeout.md). **991 tests pass; +53 over the v1.0 baseline of 938** (includes a one-line lexer fix that closes the 12 pre-existing CRLF-cascade failures). All seven exit criteria in §Exit criteria are met. Two sessions shipped MVP-shaped — Session 5 (save schema versioning builtins; `save SaveSlot:` block defers to v1.0.2) and Session 6 (persistent-state stdlib registry; parser sugar defers to v1.0.2) — closing the functional intent of the original spec.

---

## Thesis

v1.0 proves a Twe developer **can** ship a Survivors-class game (`examples/survive_beta/`, 1,264 LOC, builds to a self-extracting `.exe`). v1.0.1 makes that experience **good**: game feel that calls one function, audio that doesn't pop on 200-overlap, saves that survive a patch, lighting that doesn't need a custom shader, and a contributor LSP that handles cross-module rename.

The release is **call-and-go for the parts that matter**: VFX, lighting, audio, save migration. Everything proceduralised — no cloud assets, no CDN dependency, no determinism break against the Phase 29 replay contract.

---

## Scope filter

Every feature in this plan must clear three gates:

1. **Sessionable.** 1–3 sessions per the per-commit discipline in [`CLAUDE.md`](../CLAUDE.md) §Working contract. Anything phase-sized goes to v1.1.
2. **Survivors-pressured.** Either `examples/survive_beta/` or the `TweGame.md` Track A `glyph_runner` proves it. Speculation gets deleted.
3. **Five-principles clean.** Game concepts first-class (1), one obvious way (2), no silent footguns (3), AI-legible (4), engine-native (5). Cite the principle on every commit.

---

## On cloud-stored assets — decided

A standing question raised during planning: *should v1.0.1 host VFX / audio packs in a Twe-owned CDN that scripts fetch at runtime?* **No.** Four reasons:

1. **Determinism.** Phase 29 `replay.record` / `replay.play` is a reproducibility contract. A remote asset can change between record and replay. The replay story collapses the moment a network endpoint can shift.
2. **Self-extracting `.exe` thesis.** Phase 12 pitches Twe as "no engine dependency, single self-extracting `.exe`." Cloud-fetched assets make the binary phone-home on first run; that's a different product.
3. **LLM grounding (Phase 33).** `twec verify` can verify a `fx.hit_flash(...)` call against the stdlib JSON manifest. It cannot verify `assets.fetch("https://...")`. Cloud assets are precisely the hallucination class Twe is built to eliminate.
4. **Project-as-CDN risk.** Hosting third-party assets makes the Twe project legally and operationally responsible for them. Not appropriate for a one-maintainer language.

**Replacement pattern.** v1.0.1 ships **fully procedural effects** (`fx.*`, `light2d.*`) that are generated from code at runtime, plus an opt-in `assets.download_to_cache(url, sha256)` helper for users who choose to fetch their own assets *with the SHA verified at the call site*. The Twe project never hosts anything; the binary stays offline-first.

This decision goes in [`06-design-document.md`](06-design-document.md) Appendix B before the first v1.0.1 session lands.

## Sessions

Sessions are numbered `1.0.1-N`. Each ends with a runnable artifact and a commit prefixed `v1.0.1-N:`.

### Session 1 — `fx.*` procedural VFX library *(headline)* — ✅ shipped 2026-05-12

**Goal.** Survivors-class game feel in one function call per effect. No assets, no PNGs, no cloud.

**Surface** (~12 builtins, all routed through the existing `particles` block + `visual` block + Phase 9 WGSL codegen):

```twe
fx.hit_flash(entity, duration: 0.06)
fx.screen_shake(amount: 8.0, duration: 0.25, falloff: "ease_out")
fx.hit_stop(duration: 0.05)
fx.damage_number(at: pos, value: 42, color: color.red)
fx.crit_text(at: pos, value: 100)
fx.death_burst(at: pos, count: 12, color: color.cyan)
fx.pickup_pop(at: pos, color: color.yellow)
fx.dash_trail(entity, length: 0.4, color: color.white)
fx.level_up_ring(at: pos, color: color.gold)
fx.blood_splat(at: pos, dir: vec2)
fx.muzzle_flash(at: pos, dir: vec2)
fx.ground_shockwave(at: pos, radius: 60)
```

**Files.** New `src/fx.rs`, builtin registration in [`src/stdlib.rs`](../src/stdlib.rs), tween infrastructure shared with Session 2.

**Principles.** P1 (VFX is the canonical first-class game concept currently in library shape), P2 (one call per effect), P4 (every effect surfaces in `twec stdlib --json`).

**Test.** `examples/fx_demo.twe` exercises all 12; `survive_beta` rewritten to use `fx.hit_flash` on slime damage and `fx.screen_shake` on boss attacks.

### Session 2 — `tween.*` interpolation primitives

**Goal.** Deterministic easing for menus / damage numbers / pickup magnetism. Pure functions of `t`; replay-safe.

```twe
tween.to(target: ref, value: pos, duration: 0.4, ease: "ease_out_cubic")
tween.bounce(value: ref, from: 1.0, to: 1.15, duration: 0.15)
tween.shake_value(name: "ui.score_scale", amount: 0.2, duration: 0.3)
```

**Files.** New `src/tween.rs`. Used internally by Session 1.

**Principles.** P2 (one obvious way to animate a value), P3 (deterministic — eases are pure functions; no hidden global state).

**Test.** `tests/programs/tween.twe` snapshots a 60-tick lerp; should be byte-identical across runs.

### Session 3 — `light2d.*` dynamic 2D lighting

**Goal.** Night-time / dungeon levels for Survivors clones. Cheap additive multi-light pass; optional 1-bounce AABB shadow caster.

```twe
light2d.add(at: torch_pos, color: color.warm_orange, radius: 120, flicker: 0.15)
light2d.ambient = color.rgb(0.05, 0.05, 0.1)
light2d.cast_shadows(from: tilemap_solid_cells())
```

**Files.** New WGSL shader in [`src/visual_wgsl.rs`](../src/visual_wgsl.rs); runtime integration in [`src/play.rs`](../src/play.rs). 16 lights max — same budget shape as Phase 20's point-light pass on the 3D side.

**Principles.** P1 (lighting is a game concept), P5 (engine-native — runs through the existing WGSL pipeline, not a script overlay).

**Test.** `examples/dungeon_demo.twe` — a tilemap room with three torches and a moving player light.

### Session 4 — Audio polish: pooling + ducking + music layers

**Goal.** Real Survivors audio. 200 overlapping hits don't clip; boss music ducks SFX; dynamic music layers in/out with enemy count.

```twe
sound.pool("sfx/hit.wav", max_voices: 8)
sound.duck(channel: "sfx", to: 0.3, while_playing: "music/boss_intro.wav")
music.layer("base.ogg", weight: 1.0)
music.layer("drums.ogg", weight: enemy_count / 50.0)
music.crossfade("level1.ogg", "level2.ogg", duration: 2.0)
```

**Files.** Extension of the Phase 8 session 5 audio code in [`src/stdlib.rs`](../src/stdlib.rs); new `music.*` namespace.

**Principles.** P1 (music layers are a first-class concept, not a manual mixer), P3 (`sound.pool` prevents the silent-failure-mode where overlapping plays clip and you can't tell why).

**Test.** `examples/audio_demo.twe` extended with pool + duck + layer cases. Survivors clone uses pooled SFX for slime hits.

### Session 5 — `save SaveSlot:` block + version migrations

**Goal.** Close the [`CLAUDE.md`](../CLAUDE.md) "What is open" item. Any v1.0.1 patch is the moment a real shipping game's saves break — this session is the answer.

```twe
save SaveSlot:
    version: 3
    var hp: int = 100
    var level: int = 1
    var inventory: list[Item] = []

    migration from 2:
        pass  # auto-add new field with default

    migration from 1:
        level = math.max(1, level)
```

**Files.** Lexer keyword in [`src/lexer.rs`](../src/lexer.rs), parser block in [`src/parser.rs`](../src/parser.rs), AST node in [`src/ast.rs`](../src/ast.rs), codegen against the Phase 22 typed `save.*` namespace in [`src/eval.rs`](../src/eval.rs) and [`src/vm.rs`](../src/vm.rs), doc in [`07-save-system.md`](07-save-system.md).

**Principles.** P1 (save state is a game concept; right now it's a bare API), P3 (migrations make schema drift a compile-time error, not a runtime corrupted-save).

**Test.** `tests/programs/save_migrate.twe` writes a v1 save with the old layout, runs the program with a v3 SaveSlot, asserts the migration ran.

### Session 6 — Per-state pause opt-out

**Goal.** Close the second [`CLAUDE.md`](../CLAUDE.md) "What is open" item. Pause menus, debug HUDs, and toast notifications all need a state that *isn't* paused by the global pause.

```twe
state pause_menu:
    pause: false           # never paused

state hud_overlay:
    persistent             # alias — never paused
```

**Files.** Parser sugar on `state` blocks ([`src/parser.rs`](../src/parser.rs)), eval-side pause filter in [`src/eval.rs`](../src/eval.rs), VM mirror in [`src/vm.rs`](../src/vm.rs).

**Principles.** P2 (the obvious way to opt out of pause is `pause: false`; no API call, no global flag), P3 (without this, debug overlays go invisible the moment the player pauses — silent footgun).

**Test.** `examples/pause_demo.twe` updated to demonstrate a persistent HUD state during pause.

### Session 8 — Camera2D: follow + zoom + cinematic pan

**Goal.** Survivors / platformer / RPG all want follow-cam with deadzone + bounds. Currently scripted by hand in `examples/survive_beta/main.twe`.

```twe
camera2d.follow(entity, lerp: 0.15, deadzone: (60, 40))
camera2d.zoom_to(value: 1.4, duration: 0.6)
camera2d.cinematic_pan(from: pos_a, to: pos_b, duration: 1.5)

```

**Files.** Extension to Phase 9 session 2 camera in [`src/stdlib.rs`](../src/stdlib.rs).

**Principles.** P1 (follow-cam with deadzone is a 2D-game concept, not a math exercise the user re-implements per game).

**Test.** `survive_beta/main.twe` rewrites its follow logic to call `camera2d.follow`. Net LOC delta should be ≤ 0 (this is a polish session, not a feature growth).

### Session 9 — LSP cross-module go-to-def + rename

**Goal.** Biggest contributor-DX bump. Phase 13 shipped modules; Phase 6 + 13 LSP does hover + diagnostics + autocomplete. v1.0.1 lands cross-module navigation.

**Surface.**
- Go-to-definition across `import` boundaries.
- Find-references on entity / function / variable names.
- Rename refactor — AST-driven, multi-file safe.

**Files.** [`src/lsp.rs`](../src/lsp.rs) (1,515 LOC currently); the AST round-trippability from Phase 3 + module resolver from Phase 13 are the load-bearing pieces.

**Principles.** P4 (AI-legible AST — the same property that makes LLM authoring work makes safe rename mechanical).

**Test.** Hand-driven against `examples/modular_math_demo/` and `examples/modular_audio_demo/`; no test-harness regression in the LSP integration tests.

### Session 10 — Replay-on-crash

**Goal.** Every crash report bundle contains the last ~30 seconds of input. Users post a 100KB reproducible bundle instead of "it crashed when I clicked a thing."

**Mechanism.** Phase 29's `replay.record` is always-on (deterministic input ring). Phase 11's crash reporter ([`src/window_focus.rs`](../src/window_focus.rs) + `twec-crash-*.log`) gets a hook that writes the last 30s of input frames next to the crash log.

**Files.** Wiring in [`src/replay.rs`](../src/replay.rs) ↔ crash reporter. New CLI subcommand `twec replay <crash.bundle>` to replay the bug.

**Principles.** P3 (no silent footguns — crash bundles that aren't reproducible *are* a silent footgun for the maintainer).

**Test.** `tests/replay.rs` extended: panic mid-game, assert the bundle replays to the same panic.

### Session 11 — CI perf-bench snapshot + regression alert

**Goal.** Keep the **3× bytecode-VM speedup gap** from Phase 8.5 bounded instead of growing silently. Phase 11 shipped `benches/vm.rs`; v1.0.1 wires it into CI with a checked-in baseline.

**Mechanism.** Same pattern as Phase 35's `docs/api-snapshots/2026-05-10-baseline.json` — a checked-in `docs/perf-snapshots/v1.0.1-baseline.json` with criterion's median timings on `sum_loop` / `float_loop` / `fib_recursive`. PR delta computed by a new `twec perf-diff` subcommand. >5% regression fails CI.

**Files.** `.github/workflows/ci.yml`, new `src/perf_snapshot.rs`, baseline JSON in `docs/perf-snapshots/`.

**Principles.** P5 (engine-native — the VM is the runtime; a regression in the VM is a regression in every game ever shipped on Twe).

**Test.** A deliberate `binary_arith` slowdown commit must fail CI; the same commit reverted must pass.

### Session 12 — Localization plurals

**Goal.** Close the third [`CLAUDE.md`](../CLAUDE.md) "What is open" item. `lang.t` and `lang.tf` shipped in Phase 10 session 10; ICU-style plurals deferred.

```twe
lang.t_plural("enemies_killed", n, { count: n })
# en: "1 enemy killed" / "5 enemies killed"
# pl: complex three-form rule applied
```

**Surface.** Built-in plural rules for at least `en`, `es`, `de`, `ja`, `pl`. Custom rules per-locale via `lang.set_plural_rule(locale, fn)` for the long tail.

**Files.** [`src/stdlib.rs`](../src/stdlib.rs) extension; doc in [`06-design-document.md`](06-design-document.md) §7 lang.

**Principles.** P1 (i18n is a shipping-game concept), P3 (without proper plurals you get "1 enemies killed" — a silent ugliness footgun visible to every player).

**Test.** `tests/programs/lang_plural.twe` covers each shipped locale.

### Session 13 — `twec doctor`

**Goal.** Diagnostic command. Saves 80% of "why doesn't `play3d` work on my machine" issues during the v1.0 community ramp.

**Reports.**
- Rust toolchain version + target triple.
- Detected GPU adapter (wgpu probe).
- Optional SDK presence: Steamworks, Android NDK, Xcode.
- Cached asset directory size.
- Last 3 crash log paths (Phase 11 reporter output).
- Active feature flags.

**Files.** New `src/doctor.rs`; subcommand in [`src/cli.rs`](../src/cli.rs).

**Principles.** P4 (diagnostics are machine-readable — `twec doctor --json` for the LLM-grounded support workflow).

**Test.** `tests/cli.rs` invokes `twec doctor --json` and asserts the schema.

## Exit criteria

The v1.0.1 release tag goes up when all of these are true:

1. All 13 feature sessions land with their test in `tests/programs/` or `tests/`.
2. **Net test count is ≥ +20** vs the v1.0 baseline (938).
3. `cargo build --release` zero warnings on Windows + macOS + Linux + WASM targets.
4. `cargo clippy --release --all-targets -- -D warnings` clean.
5. `examples/survive_beta/main.twe` rewritten to use `fx.*`, `camera2d.follow`, `sound.pool`, and `save SaveSlot:` — and its LOC count goes **down** or holds steady. v1.0.1 is a polish release; the same game in fewer lines proves the additions are first-class.
6. The Phase 11 perf baseline JSON exists at `docs/perf-snapshots/v1.0.1-baseline.json` and CI's `perf-diff` gate is green.
7. Closeout note shipped per Session 14.

## Anti-goals

Things explicitly **not** in v1.0.1, with the phase they re-enter:

- **VM dispatch-loop rework** (computed-goto / direct-threaded). The honest deferral from Phase 8.5; biggest single perf win available. **Phase-sized — re-enters v1.1.** Session 11's CI gate is the prerequisite either way.
- **Browser-3D wgpu port.** Honest deferral from Phase 38. Re-enters when Firefox-stable + Safari-stable hit usable wgpu coverage.
- **Live mobile safe-area hooks** (`UIViewController.safeAreaInsetsDidChange`, `WindowInsetsCompat`). Phase 39 deferral. Re-enters when a community contributor has live mobile hardware to test on; not in `.1`.
- **Steam Workshop runtime.** Phase 41 `workshop.*` stubs exist; the real publish/subscribe pipeline needs Steamworks ISteamUGC binding work, which is feature-flag-gated and beyond `.1`.
- **MMO server runtime.** Phase 41 honest deferral. Re-enters in v2.0 or never — that's the explicit position in the MMO RFC.
- **Cloud-hosted asset CDN.** Decided against; see §"On cloud-stored assets" above. The procedural `fx.*` + `light2d.*` libraries are the answer instead.
- **Macro / metaprogramming system.** Off the table per [`CLAUDE.md`](../CLAUDE.md) Anti-patterns.
- **List comprehensions, `then` keyword expansion.** Snake's NP3 / NP10 deferrals; not pressured by Survivors. Stay open.

| 8 | 2. `tween.*` | Used by 1; ship if 1 ships. |
| 9 | 8. `camera2d.follow` | Polish for survive_beta. |
| 10 | 6. Per-state pause opt-out | Closes an open item; tiny. |
| 11 | 7. Nine-slice panels | UI polish. |
