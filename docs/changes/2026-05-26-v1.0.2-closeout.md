## Honest deferrals

The v1.0.2 plan's [Anti-goals](../v1.0.2-plan.md#anti-goals) list was respected; every phase-sized item stays deferred. Two session-internal deferrals worth naming:

1. **Session 3 — `entity X: lod = [...]` / `entity X: rollback = true` parser sugar.** Cut at the planned 30-minute spike. Three blockers surfaced:
   - Tuple-with-named-fields (`(distance: 0, mesh: "...")`) isn't real Twe — those forms are kwargs to function calls, not standalone literals. The `world.set_lod_chain(class, assets, switches)` builtin takes two parallel lists; sugar lowering would have to diverge from the v1.0.1 plan's sketch.
   - Rollback mode is a *global* flag (`net.set_mode("rollback")`); no per-entity hook exists today, so `entity Fighter: rollback = true` has no clean lowering target.
   - Both halves are defer-on-defer: Phase 32 wgpu render integration and Phase 37 eval-side rewind engine remain phase-sized; layering ergonomic sugar over absent runtimes doesn't deliver shipping-game value. Re-enters in v1.1 alongside its respective runtime follow-on.

2. **Session 9 — VM-mirror was a non-event.** The Phase 32 closeout had listed "VM mirror of the new namespaces" as an honest deferral on the Phase 9 Session 7b precedent. v1.0.2's investigation found `VM::new()` (src/vm.rs:182) already calls `crate::stdlib::install` and copies every binding into the VM globals table — the 35 `world.*` / `terrain.*` builtins were reachable from the bytecode VM the whole time. The session's deliverable became a parity test (`tests/programs/world_terrain_vm_mirror.twe` + `tests/cli.rs`) that locks the path so a future regression (e.g. shadowing the `world` Object the way `entities` is shadowed) trips here rather than at a release-tag smoke test.

Two other items remain open with no v1.0.2 motion:

- **`save SaveSlot:` typed-field declarations** (`var hp: int = 100` creating save-store-backed globals — the Path A form of the v1.0.1 Session 5 spec). Phase-sized; new variable-binding mechanism in eval + VM + type checker. Re-enters in v1.1 as its own phase.
- **Per-platform input-feel measurement** of all v1.0.2 sugar paths in real `survive_beta` playtests — operator action; cargo-test parity doesn't replace eyes on the running game.

## What we learned

- **The "spike before commit" discipline is real.** Session 3 was on track to consume a multi-day effort before the 30-minute investigation found the runtime targets weren't there. The plan doc named the spike risk explicitly ("If the type checker needs to know about either field, this session splits into 3a (lod) + 3b (rollback)") — and the spike's honest outcome (cut entirely) is the right answer the discipline is designed to produce.
- **"Honest deferrals" sometimes turn out to be already-done.** Session 9's investigation found the v1.0.2 work was effectively a parity test, not a feature port. The Phase 32 closeout's deferral list was correct as written, but pessimistic about what was actually missing. The parity test does meaningful work — it locks a path that *could* regress — but the scope was much smaller than the plan estimated.
- **Parser-sugar over existing builtins keeps the scope-filter honest.** Every shipped session lowered to AST nodes the rest of the compiler already handles. Zero new variants in `Stmt` / `Expr`; zero new builtins; zero changes to eval / VM / checker / printer dispatch tables. The `Stmt::If { cond: Bool(true), then_body }` idiom (Session 1) avoided adding a `Stmt::Block` variant that would have touched 7 files.
- **Closeout-note discipline catches mis-scoped exit criteria.** The plan's exit-criterion 5 ("`survive_beta` LOC delta ≤ 0") assumed both shipped sugar paths applied to the file; only the save half did, and the block-header fixed cost makes the v1.0.1 builtin form one line shorter for a zero-migration schema. The honest update (+2 LOC, with rationale) ships here rather than being papered over.
- **A patch release after a polish release is still mostly deferral work.** v1.0.1 was 13 sessions of features; v1.0.2 is 10 sessions of closing IOUs from across the previous codebase. The work is smaller per-session but no less load-bearing — every closed deferral takes a `What is open` line off the brief.
