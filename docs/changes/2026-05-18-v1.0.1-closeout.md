## Honest deferrals

v1.0.1 was scoped to **polish**, not feature growth. The anti-goals list in [`docs/v1.0.1-plan.md`](../v1.0.1-plan.md) §Anti-goals was respected; each item is unchanged:

- **VM dispatch-loop rework** (computed-goto / direct-threading). Phase-sized; re-enters v1.1. Session 11's CI gate is now the prerequisite floor — the gap won't grow silently.
- **Browser-3D wgpu port.** Phase 38 deferral. Re-enters when Firefox-stable + Safari-stable hit usable wgpu coverage.
- **Live mobile safe-area hooks.** Phase 39 deferral. Re-enters when a community contributor has live mobile hardware.
- **Steam Workshop runtime.** Phase 41 `workshop.*` stubs remain stubs.
- **MMO server runtime.** Phase 41 deferral.
- **Cloud-hosted asset CDN.** Decided against; see `docs/v1.0.1-plan.md` §"On cloud-stored assets." The procedural `fx.*` + `light2d.*` libraries are the answer.
- **Macro / metaprogramming.** Off the table per [`CLAUDE.md`](../../CLAUDE.md) Anti-patterns.

Two session-internal deferrals worth naming:

1. **LSP cross-module rename — false-positive guarantee** (Session 9). The current implementation uses word-boundary scan with string-literal + `#`-comment skipping across every open document. False-positive renames remain possible inside `"..."` blocks that span lines or unusual contexts. A full lexer-based rename pass is a v1.1 ergonomic-pass item.
2. **`lang.set_plural_rule(locale, base_locale)` aliasing only — no Twe-side closure rules** (Session 12). Custom plural rules require invoking a Twe lambda from a Rust builtin, which would mean exposing the eval loop's `call_function` as a public API. We ship the aliasing form (route `pt-BR` through `es`, etc.) which covers the long tail without that plumbing. A closure-based form is a v1.x ergonomic-pass item.

## What we learned

- **Procedural-only is the right answer for VFX.** The cloud-CDN debate in `docs/v1.0.1-plan.md` §"On cloud-stored assets" was settled in favour of "every effect is generated from code." Shipping `fx.*` + `light2d.*` proved it — every Survivors-class effect a v1.0 game wants is one builtin call, with no asset files, no network dependencies, and no replay-determinism break.
- **Replay-on-crash is free if the determinism contract holds.** Phase 29 shipped `replay.record`; v1.0.1 Session 10 added an always-on input ring populated in parallel. The crash reporter writes both `.log` and `.replay`, and the bug-bundle workflow ("user posts both files; maintainer runs `twec replay`") works mechanically.
- **CI perf gates require a baseline more than they require a fast VM.** The 3× speedup gap from Phase 8.5 remains open — Session 11 doesn't close it. But the gap is now *bounded*: the baseline is in-repo, the diff is greppable, and any silent regression fails CI. The faster-VM follow-on is a real Phase 13+ commitment now, not a hand-wave.
- **A polish release is a feature release in disguise.** v1.0.1 was framed as "the 13 sessions that don't ship a different game"; in surface-area terms it adds **47 builtins** and four CLI subcommands. The framing matters because it kept scope honest — every addition was pressure-tested against `examples/survive_beta/` rather than speculative game shapes.
- **Closeout-note discipline survives the v1.0 boundary.** Every prior phase shipped with a closeout note; v1.0.1 follows the same pattern even though it isn't a numbered phase. That pattern remains the load-bearing mechanism by which `CLAUDE.md` stays honest.
