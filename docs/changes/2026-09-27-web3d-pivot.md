# Design Change Note — Web3D pivot (reopens the v1.0 thesis)

**Date:** 2026-09-27
**Status:** decided by the maintainer; execution begins as milestone line `web3d-M0 … M6`.
**Reopens (explicitly):** the v1.0 thesis ("ship a Vampire-Survivors-class
2D game"), "3D in maintenance mode, off the critical path", and the
bytecode-VM freeze (the VM is now scheduled for removal, not just frozen).

## Why

An in-depth audit (2026-09-27) and the maintainer's research brief
*Web3D Engine Architecture Expert Brief* (26–27 Sep 2026) together
concluded:

- **The foundation was unsound.** GC use-after-free reachable from safe
  script code (fixed in [`2026-09-27-web3d-m0-gc-soundness.md`](2026-09-27-web3d-m0-gc-soundness.md));
  dynamic scoping (a `let` inside a function leaks to globals, callees
  see the caller's parameters, module functions resolve free names in
  the importer); about 1 µs per entity `update()`.
- **Much "closed" surface is scaffolding.** `rollback` (no rewind),
  `mmo`, `console`, `workshop`, mobile, browser-3D, and the Phase 32
  `streaming` / `lod` / `cull` / `instance` modules are bookkeeping the
  renderer never consumes.
- **The brief's architecture is sound, and Twe is structurally
  positioned for it** (Rust + wgpu, one crate for WASM and native;
  `visual` blocks already compile to WGSL, the brief's "material graph").
  But the language's per-object `update()` / `render()` semantics
  encode exactly the "CPU touches every object every frame" model the
  brief rejects. So the revamp changes the **language↔engine
  contract**, not just the renderer.

The Twe *language* is the brief's "API people feel" / scene-IR layer;
the *kernel* is the brief's engine. The language's differentiator is
LLM authoring, which the brief does not consider — it must become
measured (a real benchmark), not asserted.

## The one-page spec (brief §12–13)

| Question | Answer |
|---|---|
| Genre (first vertical slice) | Top-down 3D "survivors" — merges the old 2D v1.0 goal |
| Players per instance | 1 (single-player), architected net-ready: deterministic fixed tick, input-command stream as the only sim input |
| Weakest device holding 60 fps | 2023 mid-range laptop, Chrome (WebGPU) |
| Resident VRAM cap | 512 MB |
| Renderer written or leased | Written — evolve the existing wgpu renderer; GPU-driven pieces only when a profile demands it |
| Capacity | Solo maintainer + AI, ~12 months |

## Decisions

1. **v1.0 = `survive3d` running in Chrome** (and natively from the same
   kernel). The 2D macroquad engine stays until the kernel draws
   sprites (M6), then retires.
2. **Scaffolding namespaces move behind `--features experimental`** and
   out of the stdlib manifest, LLM primer and README claims.
3. **Bytecode VM:** gated behind `experimental` in M0, deleted at M1
   exit unless its re-entry criterion (beats the tree-walker on
   `entity_update`) is met. It is no longer a parity target for new
   semantics.
4. **Architecture target:** Cargo workspace — `twe-lang` (language),
   `twe-kernel` (SoA world, renderer, assets, physics; knows nothing
   about Twe syntax), `twe-native` / `twe-web` shells, `twe-llm`
   (providers, edit protocol, benchmark), `twec`. Studio
   (`D:\IT\twe-engine`) embeds the web build in its viewport.
5. **Language contract changes** (each needs its own design note when
   it lands): lexical scoping via a resolver pass (M1); entity classes
   become archetypes whose `update(dt)` runs as a batched system, and a
   declarative `look:` block replaces per-entity drawing in 3D (M3).

## Milestones

| M | Weeks | Scope | Hard exit |
|---|---|---|---|
| M0 | 1–3 | GC soundness, experimental gate, shipping-bug fixes, truth pass | Every program agrees under `TWE_GC_STRESS=1`; wasm32 check green |
| M1 | 4–9 | Resolver + slot frames, lexical scoping, module fix, perf wins | Leak count 0; `entity_update` ≤ 500 ns native |
| M2 | 8–15 | Workspace + kernel extraction + WebGPU shell | `hello_3d` at 60 fps in Chrome and natively |
| M3 | 15–23 | SoA entities, `look:`, rotation, materials, HUD text | 5k seeking enemies at 60 fps in Chrome |
| M4 | 23–31 | `survive3d` slice + Studio viewport | 10-minute run on itch.io, no crash |
| M5 | 10–34 | Measured LLM benchmark (parallel) | Published numbers with CIs vs a Python/pygame baseline |
| M6 | 34–46 | Kernel sprites; retire macroquad | No `macroquad` dependency |

Commits use `web3d-mN: <verb> <what>`; each milestone ends with a
`docs/changes/<date>-web3d-mN-closeout.md` that reports shipped
against exit criteria. Nothing is called closed without its exit
criteria met.

**Out of scope this year:** meshlets, vis-buffer, HZB, Gaussian
splats, WebTransport / authoritative server, rollback resimulation,
MMO, console and mobile ports, compiling systems to WGSL/native, model
fine-tuning.

**Kill line:** if Twe + the verify loop does not beat the Python
baseline on the benchmark, stop marketing LLM authoring as the moat
and write a root-cause note.
