# web3d-M7 session 4: image-based lighting

**Date:** 2026-09-29
**Milestone:** web3d-M7 ([scope](2026-09-28-web3d-m7-graphics-beyond-threejs.md), [sessions](2026-09-29-web3d-m7-plan.md), previous: [PBR](2026-09-29-web3d-m7-pbr.md))
**Code:** `src/kernel/environment.rs` (new); frame bind group, `shade`, backdrop pass in `src/kernel/render.rs`

## What changed

1. **Environment maps.**
   - `RenderSnapshot::environment` names an equirect Radiance `.hdr`, with an intensity and whether to draw it as the backdrop.
   - The file comes through the host's `AssetSource` like any asset (`AssetKind::Environment`): a file natively, `fetch` or the bundle on the web.
   - It is decoded by `image` (its `hdr` feature: pure Rust, a feature of an existing dependency).
2. **Precompute, once per environment, on the GPU:**
   - equirect → a 512² cubemap with a full mip chain;
   - GGX prefiltering into a 256² specular cube, where mip *i* holds roughness *i*/5. This is Karis's split sum, with filtered importance sampling (Křivánek & Colbert) at 1024 samples.
3. **Diffuse irradiance:** 9 spherical-harmonic coefficients (Ramamoorthi & Hanrahan). They are projected on the CPU from every texel of the map, weighted by solid angle, so they are exact and deterministic.
4. **DFG lookup table.** A 64² table replaces Karis's analytic fit. It is computed at startup with the same height-correlated Smith visibility the direct lights use, and the multiscatter energy compensation now reads it too.
5. **Shading.**
   - Indirect light is SH irradiance for diffuse, plus prefiltered radiance × (f0·A + B) × energy for specular.
   - Occlusion applies to diffuse, and to specular through Lagarde's specular-occlusion fit.
   - Without an environment, the ambient colour stays a uniform environment (the game's current path).
6. **Backdrop.** A fullscreen triangle at the far plane samples the equirect along each pixel's view ray (the camera uniform gained `inv_view_proj`), drawn only where no geometry is.
7. **Harness.** Twe now renders each scene as Cycles and Three.js do: lit only by the scene's environment (no sun, ambient or shadows), with the backdrop when the scenario asks for one.

## A loader bug the harness found

TextureTransformTest's planes have no `NORMAL` attribute. glTF requires flat normals then, and Three.js computes them. Twe's loader pointed every such vertex straight up, so every normal-less surface was lit like a floor.
- **Fix:** primitives without normals are de-indexed, and each triangle corner carries its face normal.
- **Result:** the scene went 0.287 → 0.121.
- The unit test that had pinned the old "up" fallback now pins flat normals.

## Not in this session

- **No script API for environments yet.** The kernel supports them; the game and `look:` don't expose them. A scene-level environment/sky setting is language surface, and M7's rule is that it arrives with an example and a design note, when `survive3d` adopts it (session 16).
- **Environment map rotation and exposure controls:** not needed by any scene yet.
- **The environment path in the browser:** its shaders validate (naga tests for the sky and precompute shaders), and `survive3d` runs in Chrome with the new bind group, error-free. But no web page loads an environment yet, so the precompute hasn't run under WebGPU's Tint compiler. That happens when a web scene uses it.
