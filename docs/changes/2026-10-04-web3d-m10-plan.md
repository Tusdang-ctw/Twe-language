## The milestone, in one line

> The editor becomes a place a human prefers to "VS Code + a pile of Three.js libraries."

Studio already has viewport / editor / AI / inspector / scene-tree / state-graph / console (in `D:\IT\twe-engine`, Tauri v2 + React). It has **no debugger and no profiler**. M10 adds those plus one-click publish and live editing.

## Exit criteria (from the roadmap)

1. A **debugger** — breakpoints, step, variable/entity inspection on a running game.
2. A **profiler** panel — frame-time + GC + draw-call, reusing `twec profile` + the F3 HUD.
3. **One-click publish** — desktop `.exe` + web, wrapping `twec build`.
4. **Live scene/inspector editing** without a full reload.

**Artifact:** a screen-capture flow — open, edit, breakpoint, step, profile, publish to web + exe.
**Cut line:** if a full debug adapter slips, ship breakpoint + inspect (no step-into) and track the rest.

## The two-repo split

M10 is cross-repo. The **language hooks live here** (`twe-language`); the **UI lives in `twe-engine`** (`studio/src/components/`, `studio/src-tauri/`). Language sessions land first so the UI has something to drive.

- **twe-language key files:** `src/eval.rs` (statement hook, pause/step, scope dump), `src/host3d.rs` + `src/play3d.rs` / `src/frame2d.rs` (per-frame feed), `src/profile.rs` (timing), `src/cli.rs` (a debug/publish entry the Tauri backend drives), `src/lsp.rs`.
- **twe-engine key files:** new `studio/src/components/Debugger/`, `Profiler/`, `studio/src-tauri/src/commands/`, `useLspClient.ts`, `usePlay.ts`.

## Grounded current state (2026-10-04)

- `eval::tick_frame(env, dt)` is the per-frame entry; `eval_stmt` dispatches, and statements/slots already carry `.line` (used in `RuntimeError`), so a breakpoint check at statement boundaries is feasible without new AST data.
- `profile.rs` has `TraceEvent` + `Scope` + `dump_to_path` (Chrome trace) + enable/disable — a profiler feed extends this rather than starting fresh.
- `twec build` already produces the desktop `.exe` and the web bundle; one-click publish wraps it (a `--json` result mode is the main add).
- `twec mcp` is the model for a stdio JSON-RPC control channel the Tauri backend can drive.

## Sessions

Language hooks first (1–3), then the Studio UI (4–6).

1. **Debug protocol + breakpoints (twe-language)** — a `DebugSession` (breakpoints by `file:line`, pause / resume / step-over / step-into, a hook at statement boundaries in `eval_stmt`), plus variable + live-entity inspection (serialise the current scope + entities to JSON). Exposed through a stdio JSON-RPC debug mode (the `twec mcp` pattern) the Studio drives. Headless tests: set a breakpoint, run a tick, assert it pauses at the line and the scope dump has the expected bindings; step advances one statement.

2. **Profiler feed (twe-language)** — a structured per-frame sample (frame ms, sim vs render split, GC ms + bytes-alive via the existing `gc.*`, draw-call count from the renderer) exposed as a live JSON stream / ring, built on `profile.rs`. Reuses the F3 HUD's numbers. Test: a few ticks produce well-formed samples with monotonic timestamps.

3. **One-click publish (twe-language)** — `twec build --json` emits machine-readable progress + the artifact paths (desktop `.exe`, web dir) so Studio can invoke one call and show links. Test: `--json` on a tiny project yields parseable output naming the artifacts.

4. **Debugger panel (twe-engine)** — breakpoint gutter in the Monaco editor, step controls, a variables/entities tree, driven by session 1. Artifact: set a breakpoint, step, inspect.

5. **Profiler panel (twe-engine)** — a frame-time graph + GC + draw-call readout driven by session 2.

6. **One-click publish + live edit (twe-engine)** — a publish button (→ session 3, shows exe + web links) and live scene/inspector edits applied to the running game without a full reload (hot-apply value changes through the existing hot-reload path). Closeout.

Sessions may merge/split; the debugger (1 + 4) is the centre of mass and the cut-line candidate.
