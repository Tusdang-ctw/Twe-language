# web3d-M11 plan — game-feature depth

**Opened:** 2026-10-05 (after M10 closed; M8, M9 closed).
**Line:** creation-parity (M8–M12) — [`2026-10-04-creation-parity-plan.md`](2026-10-04-creation-parity-plan.md).
**Commit prefix:** `web3d-m11:`. Closeout: `docs/changes/<date>-web3d-m11-closeout.md`.

## The milestone, in one line

> The 3D features a real game needs that Twe still lacks — proven by a reference game that stands next to a comparable Three.js game.

## Reference game (locked with the maintainer 2026-10-05)

**A new small 3rd-person action slice — Tunic-like.** A hero with blended walk/run/idle locomotion and a sword attack, a few enemies, a 3rd-person camera, and a physics-joint element (a swinging rope bridge / chain). Playable natively and in a browser. This game choice is what scopes the features below (per the roadmap, "choose by the reference game"). **Net rollback is NOT in scope** (not a net-twitch game); WebXR is not in scope.

**Artifact:** `examples/action3d/` running in a browser, standing next to a comparable Three.js scene.

## Grounded current state (2026-10-05 audit)

- **Animation:** `mesh_anim.play / stop / blend / current / advance` exist. `compute_skinned_joint_matrices` already does a **2-clip lerp/slerp blend** (`AnimSnapshot.blend_clip` + `blend_t`). **Missing:** a smooth **crossfade on clip change** (`play()` hard-switches, so walk→attack pops) and a convenience **blend-by-parameter** (walk↔run by speed). No blend tree / anim state machine.
- **Physics:** `src/physics3d.rs` already instantiates and steps rapier's `ImpulseJointSet`, `MultibodyJointSet`, `CCDSolver` — but **no script builtins create joints or toggle CCD** (Phase 18 deferred them). `physics.body / static_* / character / character_move / raycast / collisions` exist.
- **Hero asset:** `examples/survive3d/assets/hero.glb` is a skinned, animated (walk/idle) model generated by `tests/gen_survive3d_hero.rs` — a starting point; the action slice may add an `attack` clip.

## Sessions

Language features first (testable headlessly), then the game (content; GPU/visual verification is a maintainer step).

1. **Animation depth (twe-language)** — a smooth **auto-crossfade** when the active clip changes (`play()` eases from the old pose to the new over a short time via the existing 2-clip blend machinery), plus `mesh_anim.blend(h, a, b, t)` ergonomics confirmed for a speed-driven walk↔run blend. Headless tests on the blend/crossfade math. Key files: `src/kernel/render.rs` (AnimSnapshot + `compute_skinned_joint_matrices`), `src/host3d.rs` (mesh_anim state), `src/stdlib.rs`.
   **DONE 2026-10-05.** `play()` crossfades: on a clip change the old clip becomes the blend target at full weight and `blend_t` ramps 1→0 over `DEFAULT_CROSSFADE` (0.15 s), configurable per-mesh via the new `mesh_anim.set_crossfade(h, secs)` (0 = hard switch). A new `AnimSnapshot.blend_time` + `MeshAnimEntry.blend_time` lets the outgoing clip animate on its own time (and keeps an explicit `blend()` partner in sync); `compute_skinned_joint_matrices` reads it for the secondary. Test `mesh_anim_crossfade_ramps_then_clears`; survive3d headless-GPU render still 4/4; native + wasm clippy clean. **Also fixed a latent M10 bug:** `debug::DEBUG_ACTIVE` was a process-global atomic while the session is thread-local, so parallel debug sessions gated each other — made it a thread-local `Cell<bool>` (debugging is per-thread).

2. **Physics joints + CCD (twe-language)** — expose builtins over the rapier sets that already step: `physics.fixed_joint`, `physics.revolute_joint`, `physics.spherical_joint`, `physics.prismatic_joint`, `physics.remove_joint`, `physics.set_ccd(body, on)`. Tests: build a chain, step it, assert it hangs/swings; CCD toggles. Key files: `src/physics3d.rs`, `src/stdlib.rs`, `docs/06` §7.
   **DONE 2026-10-05.** All six builtins ship (joints take two body handles + local anchor points, plus an axis for revolute/prismatic; return a joint handle or error on an unknown body). `PhysicsWorld` gained the joint-handle map + methods over the already-stepped `ImpulseJointSet`/`CCDSolver`; `rb.enable_ccd` for `set_ccd`. Test `tests/physics_joints.rs` (a spherical joint holds a body up vs a free body that falls; `remove_joint` lets it drop; `set_ccd` + unknown-handle reporting). Native-only (gated like the rest of `physics.*`); native + wasm clippy clean.

3. **Reference game — scaffold + 3rd-person controller (examples/action3d)** — hero + 3rd-person orbit camera + KCC movement + blended locomotion (idle/walk/run by speed, using s1). A gen fixture for any new asset. Headless: it parses, verifies, and ticks.
   **DONE 2026-10-05.** `tests/gen_action3d_hero.rs` generates `examples/action3d/assets/hero.glb` with four clips (walk / run / idle / attack). `examples/action3d/main.twe`: a hero on a procedural grass ground, WASD movement (Shift to run), a smoothed 3rd-person chase camera behind the heading, and **crossfaded locomotion** — idle↔walk↔run picked by a smoothed speed, each `mesh_anim.play()` crossfading (s1). `twec verify` clean (0/0); ticks 120 frames headless; examples_run green.

4. **Combat — attack + enemies (examples/action3d)** — attack on input (crossfade to an `attack` clip), a hit test, a few enemies with simple chase AI + health + death.

5. **Physics element — swinging bridge/chain (examples/action3d)** — a chain of bodies linked by s2 joints the hero can push through / cross.

6. **Polish + web build + measured artifact + closeout** — lighting/materials polish (IBL/shadows/bloom as survive3d uses), a browser build, a short comparison vs a Three.js equivalent, and `docs/changes/<date>-web3d-m11-closeout.md`.

Sessions may merge/split. The features (1–2) are the high-confidence, testable core; the game (3–6) is content whose *visual polish + "stands next to Three.js"* is a maintainer GPU step (as survive3d's was).

## Rules (inherited)

`web3d-m11:` commits; a closeout against these exit criteria. Clippy clean on default + `wasm32`; `cargo test` green; docs updated in the same commit. Every session ships a runnable artifact.
